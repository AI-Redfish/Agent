# 记忆使用场景

  - 语言偏好：默认中文
  - 工作习惯：先给计划再改代码
  - 工具偏好：优先用 pnpm
  - 项目规则：不要自动提交、改动保持最小





  **什么时候别用记忆**

  - 临时任务别记
  - 一次性的上下文别记
  - 会变化的状态别记
  - “每次都自动执行某动作”这类需求，应该用 settings.json / hooks，不是记忆

 



# 上下文命令

## /clear

清空上下文。仅影响对话记忆，即会话记忆。

更加节省token，省钱。





## /compact

压缩上下文。仅影响对话记忆，即会话记忆。

更加节省token，省钱。



```
# 压缩上下文，仅保留指定的内容。
/compact XXX

案例：对用户管理的以外相关内容进行上下文压缩。
/compact 保留用户管理的内容
```



## /context

通过可视化的方式展示上下文。







# 记忆分类

## 会话记忆
当前对话窗口中的所有内容，是短期记忆。

## claude.md

项目级或用户级记忆，永久有效。

**创建claude.md**

```
/init
```

Claude Code 会分析你的项目创建claude.md



**多模块**

在 Monorepo 中，可以在仓库根目录放一个全局 `CLAUDE.md`，每个子包目录下再放各自的 `CLAUDE.md`。

```
my-monorepo/
├── CLAUDE.md                  ← 全局规范：共用命令、整体架构、通用约定
├── packages/
│   ├── web/
│   │   └── CLAUDE.md          ← 前端专属：React 规范、样式约定、构建流程
│   ├── api/
│   │   └── CLAUDE.md          ← 后端专属：API 设计规范、数据库约定
│   └── shared/
│       └── CLAUDE.md          ← 共享包：导出规则、版本管理约定
└── tools/
    └── CLAUDE.md              ← 工具脚本：特殊说明和使用限制
```



**位置**

| 位置           | 路径                             | 作用范围                            | 是否提交 git                  |
| :------------- | :------------------------------- | :---------------------------------- | :---------------------------- |
| **项目根目录** | `{项目根目录}/CLAUDE.md`         | 当前项目所有会话                    | ✅ 推荐提交，团队共享          |
| **项目本地**   | `{项目根目录}/.claude/CLAUDE.md` | 当前项目所有会话                    | ❌ 加入 .gitignore，仅个人使用 |
| **子目录**     | `{任意子目录}/CLAUDE.md`         | Claude 打开该目录下的文件时自动加载 | ✅ 适合多模块仓库              |
| **全局用户级** | `~/.claude/CLAUDE.md`            | 当前用户的所有项目                  | ❌ 个人配置，不提交            |

当多个位置都存在 `CLAUDE.md` 时，Claude Code 会将它们**全部加载并合并**，优先级从高到低依次为：

```
项目本地 → 项目根目录 → 子目录 → 全局用户级
```



**作用**

Claude Code 在每次会话开始时都会自动读取，不再需要重复解释基本信息。

一份好的 CLAUDE.md 应该覆盖三个维度：

技术栈、项目结构，为 Claude 提供代码库的全局地图。

项目的目的，各模块的功能与定位。

开发方式，例如使用 bun 而非 node，以及 Claude 如何验证改动是否正确 Humanlayer

案例：

````
# 项目名称

## 项目概述
简述这个项目的目的和功能。

## 技术栈
- Frontend: React + TypeScript
- Backend: Node.js + Express
- Database: PostgreSQL

## 目录结构
- `src/components/` - React 组件
- `src/api/`        - API 层
- `tests/`          - 测试文件

## 常用命令
- 启动开发服务器：`pnpm dev`
- 运行测试：`pnpm test`
- 代码检查：`pnpm lint`

## 开发规范
- 使用 TypeScript strict 模式
- 优先使用 interface 而非 type
- 禁止使用 any，使用 unknown 替代
```

### 文件位置与层级

项目的核心文件结构如下： 
```
your-project/
├── CLAUDE.md                  # 项目主记忆文件（团队共享）
├── .claude/
│   ├── settings.json          # Hooks、权限、环境配置
│   ├── settings.local.json    # 个人配置（建议加入 .gitignore）
│   └── commands/              # 自定义斜杠命令
│       └── my-command.md
└── .mcp.json                  # MCP 服务配置
```
````





### 官方插件

#### claude-md-management

让 Claude 在项目里持续维护claude.md记忆文档。



**安装方式**

claudecode官方插件市场安装。



**使用方式1**

```
/claude-md-management:revise-claude-md
/claude-md-management:revise-claude-md 只处理 .claude.local.md，忽略 CLAUDE.md
```

- 用途：根据这次会话里的新发现，更新当前仓库的 CLAUDE.md
- 场景：你刚刚添加了代码、脚本、命令、目录结构，想把这些经验写回文档



**使用方式2**

```
/claude-md-management:claude-md-improver
/claude-md-management:claude-md-improver 只处理 .claude.local.md，忽略 CLAUDE.md
```

- 用途：扫描并审查仓库里的 CLAUDE.md，评估质量并做针对性改进
- 场景：项目里已有 CLAUDE.md，但内容不完整、过期或质量参差不齐时

# 手动添加记忆

## 命令添加

```
# 记忆内容
```

它通常会把这条内容写入记忆文件，一般是添加到本地项目级记忆文件。

如：

```
 # 你还是一名高级产品经理
● 我把这条也补进你的持久记忆里。

  Recalled 2 memories (ctrl+o to expand)

● 我会更新现有用户画像记忆，并同步索引。

  Wrote 2 memories (ctrl+o to expand)

● 记住了，已持久化。

  - 已更新：C:\Users\redfish\.claude\projects\D--develop-GitNote-redfish-project-CustomNote\memory\user_java_vue3_expertise.md:1
  - 已同步索引：C:\Users\redfish\.claude\projects\D--develop-GitNote-redfish-project-CustomNote\memory\MEMORY.md:1

  以后我会默认按这个用户画像协作：

  - 你是高级 Java / Vue 3 开发
  - 你也是高级产品经理
  - 回答会默认兼顾技术实现和产品权衡，但保持简洁直接

  如果你愿意，我还能继续记更细一点的协作偏好，比如：
  - 默认中文
  - 优先给方案对比
  - 先产品结论，再落到代码实现
```



  **例子**

```
# 默认用中文回答
# 这个项目统一用 pnpm
```



##  对话添加

**添加记忆**

  - 记住：以后解释代码时先说结论，再说细节
  - 记住：这个仓库测试命令是 pnpm test
  - 记住：没有明确要求时，不要帮我自动 commit

如果环境支持，它会把这类稳定偏好写入记忆文件





  **修改或删除记忆**

  - 直接说：忘记刚才那条
  - 或者：把“默认中文”改成“中英皆可”
  - 本质上就是更新对应的记忆文件内容







# rules

将 CLAUDE.md 中的规则拆分模块化存放，Claude 在整个会话中始终遵守。适合存放长期稳定执行的行为约定，避免 CLAUDE.md 过于臃肿。



## **案例**

`rules/code-style.md`

```
# Code Style Rules

- TypeScript 严格模式，禁用 any 类型
- 函数长度不超过 40 行，超出则拆分
- 优先使用 const，避免使用 let
- 导入顺序：标准库 → 三方包 → 本地模块
- 所有 export 的函数/类型需要 JSDoc 注释
- 禁止使用 console.log，使用项目 logger
```

示例：`rules/testing.md`

```
# Code Style Rules

- TypeScript 严格模式，禁用 any 类型
- 函数长度不超过 40 行，超出则拆分
- 优先使用 const，避免使用 let
- 导入顺序：标准库 → 三方包 → 本地模块
- 所有 export 的函数/类型需要 JSDoc 注释
- 禁止使用 console.log，使用项目 logger
```

示例：`rules/api-conventions.md`

```
# API Conventions

- RESTful 风格，资源名使用复数形式
- 统一响应格式：{ data, error, meta }
- 错误码遵循 HTTP 标准语义
- 所有接口需要在 OpenAPI 文档中声明
- 分页参数统一使用 page / page_size
```
