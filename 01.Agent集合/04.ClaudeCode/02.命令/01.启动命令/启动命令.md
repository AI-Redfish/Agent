

# 无参数

```
claude
```

进入claude交互。





# -p

```
claude -p "用户提示词"
```

一次性交互，仅用于一次性问答，执行完成后退出。



**无-p**

执行一次性任务，并可以继续执行任务。

```
claude 'task'
```







# worktree

```
步骤1：创建worktree

# 创建名为 "feature-auth" 的 worktree 并启动 Claude
claude --worktree feature-auth
 
# 再开一个会话，处理另一个任务
claude --worktree bugfix-123

# 自动生成随机名字，比如 "bright-running-fox"
claude --worktree

步骤二：
切换分支。
claude --worktree命令创建的worktree默认是基于远程main分支创建的新分支(一般想要基于某个分支创建新分支)。
根据自己的需要，创建符合自己要求的新分支。命令参考如下：
!git checkout -b 新分支名称 基础分支名
```



所有 Worktree 默认存放在 <你的仓库>/.claude/worktrees/<名字>/ 目录下。分支名则是 worktree-<名字>。

比如你运行 claude --worktree feature-auth，就会：

1，创建目录：.claude/worktrees/feature-auth/

2，创建分支：worktree-feature-auth

3，从默认远程分支作为起点创建新分支。



**退出时的自动清理**

这是一个很贴心的设计。当你退出 worktree 会话时：

- 没有任何改动：Claude 自动删除 worktree 和对应分支，不留垃圾
- 有改动或提交：Claude 会询问你是保留还是删除。保留就留着目录和分支，方便下次继续；删除则清理一切，包括未提交的改动



# dangerously-skip-permissions

```
claude --dangerously-skip-permissions
```

给与最好权限执行claudeCode。



**配合worktree**

可以配合claude worktree使用，在独立的workspace下让claude code肆意发挥。

```
claude --worktree hll-contract-plus --dangerously-skip-permissions

进入worktree后创建新分支
! git checkout -b 新分支名 基础分支名称
```



**配合system-prompt**

```
claude --dangerously-skip-permissions --system-prompt '直接执行所有操作，不要询问，不要解释，不要列出选项。遇到错误自动尝试修复，除非彻底失败否则不向用户汇报。'
```



# system-prompt

指定系统提示词。

使用场景：当你需要 AI 扮演一个与默认行为完全不同的角色时。

```
claude --system-prompt "你是一个只输出JSON的API，不解释任何内容。"
```



# -r

```
claude -r
```

恢复之前的某一次会话。

会话范围的权限不会自动恢复，需要你重新批准一次。



# -c

```
claude -c
```

继续上一次会话。

会话范围的权限不会自动恢复，需要你重新批准一次。



如果你在多个终端窗口都用 

```
claude --continue
```

 恢复同一个会话，所有消息会交错混在一起（就像两个人同时在同一个笔记本上写字）

对话会变得混乱。

每个终端当时只能看到自己输入的消息，但后续恢复时会看到全部交错内容。

正确做法：想并行工作时，务必使用 --fork-session，给每个终端一个干净独立的新会话。



**--fork-session**

```
claude --continue --fork-session
```

创建一个全新的会话 ID。

保留到目前为止的所有聊天历史。

原会话完全不受影响。

同样需要重新批准权限。
