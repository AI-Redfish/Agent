# Record & Replay

Record & Replay 是面向 Codex App 的“录制与回放”型插件。它的核心思想是：**用户先手动演示一次操作，Codex 记录这套操作流程，之后再让 AI 自动重复执行**。

Record & Replay 本质上可以看成一种“示范学习”能力：

```text
人工演示 -> 记录操作轨迹 -> 保存为流程 -> 回放验证 -> 成为可复用技能
```

从 Agent 架构角度看，它类似于把一次人工经验沉淀成技能库资产。后续 Agent 可以根据任务需要调用该流程，而不是每次重新推理和规划。

## 说明

**核心能力**

- **Record**：录制用户完成某个任务时的操作轨迹。
- **Replay**：按录制流程自动回放操作。
- **Reuse**：把一次性操作沉淀为可复用工作流。
- **Adjust**：当页面变化、权限不足或步骤失败时，重新录制或微调流程。


**适用场景**

- 重复填写网页表单。
- 固定后台配置流程。
- 多页面之间的数据复制和搬运。
- 周期性内容发布。
- 软件操作演示自动化。
- 个人工作流自动化。
- 给 Agent 沉淀可复用操作技能。


**不适合的场景**

- 页面布局频繁变化。
- 每次都需要复杂判断。
- 涉及验证码。
- 涉及支付、转账、删除数据等高风险动作。
- 涉及密码、Token、隐私数据等敏感信息。
- 执行失败成本高，且没有人工确认环节。

**使用建议**

- **流程拆小**：一个录制流程只覆盖一个清晰任务，不要一次录太长。
- **命名清楚**：保存流程时写明用途、适用页面、输入前提和预期结果。
- **先测试再复用**：第一次回放后必须人工检查结果。
- **避免敏感信息**：不要把密码、Token、支付信息录进流程。
- **控制权限**：只授予必要权限；如果需要完全访问，要确认风险。
- **保留人工确认**：涉及提交、发布、删除、支付等动作时，最后一步最好由人工确认。
- **维护失败记录**：如果某一步经常失败，应单独优化该步骤，而不是盲目整段重录。


## 使用

**安装**

- 插件市场安装。
- 有些版本codexAPP默认已安装。

# Computer Use

## 说明

Computer Use 适合“必须看屏幕、点界面、操作真实应用”的任务；如果任务能用命令行、API、MCP、Browser、Chrome、Playwright 等更稳定方式完成，就应优先使用那些结构化工具。

```text
优先级建议：

API / MCP / Shell / 文件操作
        ↓
Browser / Chrome / Playwright
        ↓
Computer Use
```

**适合场景**

- 测试 Codex 正在开发的 Windows/macOS 桌面应用。
- 操作 iOS 模拟器、桌面客户端或本地 GUI 工具。
- 复现只能在图形界面中出现的问题。
- 修改只能通过 UI 点击完成的应用设置。
- 查看某个没有插件、没有 API、不能直接导出数据的应用信息。
- 执行需要多个桌面应用配合的流程。

**不适合场景**

- **本地 Web 应用测试**：优先用 Codex in-app Browser。
- **稳定数据读取和批量操作**：优先用 API、数据库、MCP 或脚本。
- **需要频繁重复的固定流程**：优先沉淀为脚本、MCP 工具、浏览器自动化或 Record & Replay。
- **涉及密码、支付、转账、删除、授权、隐私设置的任务**：需要用户在场并逐步确认。
- **验证码、二次验证、管理员授权、系统隐私权限审批**：不应交给 Computer Use 自动完成。
- **终端应用或 Codex 自身**：官方说明中明确不适合让它自动化终端或 Codex 本身，因为这可能绕过 Codex 的安全策略。

## 使用

**安装**

1. 打开 **Codex App 设置**。
2. 进入 **Computer Use**。
3. 点击 **Install** 安装 Computer Use 插件。
4. macOS 需要按提示授予 **Screen Recording** 和 **Accessibility** 权限。
5. Windows 上需要让目标应用保持在当前活动桌面可见，因为 Windows 下 Computer Use 会接管前台鼠标和键盘输入。

**使用**

在提示词里明确要求 Codex 使用 Computer Use，或者直接提到 `@Computer`、`@AppName`。关键是把目标应用、起始窗口、操作流程和验收结果说清楚。

示例：
```
@computer-use 打开 @Weixin 聊天切换到“微信传输助手”，发送消息“你好”
```



```text
使用 @Computer 打开桌面应用，复现登录页按钮点击无响应的问题。
请每完成一步都确认当前界面状态，如果需要提交或修改配置，先停下来让我确认。
```

```text
打开 @Chrome，检查我已经登录的后台页面中这个菜单是否可以正常进入。
不要读取 Cookie、密码或浏览器本地存储，只根据可见页面判断。
```



**Windows 使用特点**

Windows 还可以用本地配置控制哪些应用允许或拒绝 Computer Use 自动使用：

```toml
[apps]
allowed = ["mspaint.exe"]
denied = ["calc.exe"]
```

该配置位于 `$CODEX_HOME/computer-use/config.toml`。被拒绝的应用优先级高于允许列表；不在列表中的应用通常会触发权限确认。

**macOS 使用特点**

macOS 需要额外授权：

- **Screen Recording**：允许 Codex 看见目标应用。
- **Accessibility**：允许 Codex 点击、输入和操作界面。

macOS 还有 Locked Computer Use 场景：开启后，Codex 可以在 Mac 锁屏后继续执行受限的 Computer Use 任务。官方说明里强调它不是通用远程解锁能力，只服务于当前受信任的 Computer Use 任务，并带有时间窗口、屏幕遮盖、本地输入检测后重新锁定等保护措施。



# Chrome

Chrome 是 Codex Browser 官方插件体系中的一个浏览器控制场景。当前本机可见的 OpenAI bundled Browser 插件 manifest 中明确包含 `chrome` 关键字，并说明该插件用于控制 Codex 内置浏览器以及在需要时控制 Chrome。Chrome 模式适合用户明确要求使用 Chrome，或者任务必须依赖已有 Chrome 标签页、登录态、浏览器配置文件、扩展插件、真实站点会话时使用。例如：调试依赖浏览器扩展的页面、复用用户已登录的网站、检查某个已经打开的 Chrome 标签页、验证真实用户环境下的前端行为等。对于 localhost、127.0.0.1、file:// 或 Codex 内部预览页面，默认更适合使用 Codex in-app Browser；只有当任务明确需要 Chrome 的真实用户环境时，才切换到 Chrome。

## 相关说明

- **定位**：Chrome 是真实浏览器环境，适合需要用户现有登录态、扩展插件、浏览器配置文件或已打开标签页的任务。
- **与 in-app Browser 的区别**：Codex in-app Browser 更适合本地页面、localhost、file:// 和隔离测试；Chrome 更适合复用用户真实浏览器环境。
- **适用场景**：调试依赖 Chrome 扩展的页面、验证真实登录态、检查现有标签页、复现用户环境下的前端问题。
- **认证处理**：如果页面需要登录，应让用户在 Chrome 中完成登录后再继续，不应通过切换来源绕过认证。
- **隐私边界**：不要读取或导出 Cookie、localStorage、密码、会话文件、浏览器配置文件等敏感数据。
- **工具优先级**：如果任务可以通过接口、DOM 测试、命令行或 in-app Browser 完成，优先选择更隔离、更可控的方式。

## 具体使用步骤

1. **确认是否需要 Chrome**：只有用户明确要求 Chrome，或任务依赖真实登录态、扩展插件、已有标签页时才使用。
2. **准备 Chrome 环境**：用户先打开 Chrome，并确保目标网站、登录状态或扩展插件已准备好。
3. **确认目标页面**：说明要操作的 URL、已有标签页，或需要验证的具体页面状态。
4. **连接 Chrome**：通过 Codex Browser 插件选择 Chrome 作为浏览器控制目标。
5. **读取页面状态**：先观察当前可见页面，确认 URL、标题、关键元素和登录状态。
6. **执行交互操作**：按任务需要点击、输入、滚动、切换标签页或触发页面交互。
7. **验证结果**：通过页面可见状态、截图、DOM 状态或业务结果判断是否完成。
8. **遇到登录阻塞时暂停**：让用户在 Chrome 中手动登录或完成二次验证，然后再继续。
9. **避免读取敏感存储**：不要直接查看 Cookie、localStorage、密码管理器或浏览器配置目录。
10. **输出测试结论**：说明执行了哪些操作、观察到什么结果、是否存在异常，以及下一步建议。
