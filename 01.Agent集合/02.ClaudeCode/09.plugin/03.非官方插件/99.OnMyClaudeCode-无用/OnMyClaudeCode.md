# 概述

Claude Code 已经很好用了，但如果让它"自己安排任务、自己调兵遣将、自己重试直到完成"呢？

oh-my-claudecode 就是这样一个多智能体编排插件：给 Claude Code 加上 5 种执行模式、32 个专业 Agent、零学习曲线。



Claude Code 原生是"单打独斗"模式：你说一句，它做一步。oh-my-claudecode 在此基础上加了多智能体编排层，把复杂任务拆分、分

配给专业 Agent、并行执行、自动重试。



**核心**

OMC 的“魔法”不在于神秘的单词，而在于精准的模式切换 (`/mode`) 和 专业的角色调度 (`@role`)。掌握这两个组合拳，你就掌握了让 AI 

从“单兵”变“军团”的钥匙。

**HUD 状态栏-实时可见**

插件会在编辑器状态栏显示实时指标：

- 当前执行模式
- 活跃 Agent 数量
- 已完成/总任务数
- Token 使用情况





# 适用场景

**适合**：

- 需要多步骤的复杂任务
- 可并行处理的独立任务
- 需要专业知识的领域任务

**不适合**：

- 单行代码修改（原生更快）
- 简单问答（Haiku 足够）
- 不确定的探索性任务

# 模式

## 内置模式

**autopilot**

自动驾驶模式，全自动执行。



单智能体，同一个模型实例负责规划、编码、测试、修复的全流程。它做完一步，再思考下一步。



**ulw**

超级加速模式。

并行加速执行（速度提升 3-5 倍）。



尽可能快地完成大量独立任务。将大任务切分成多个相同的小块，同时扔给多个相同的 Claude 实例去跑。



**swarm**

蜂群协作模式，多角色动态协作。

模拟一个“多人团队”，动态分配任务给具有特定角色的 Agent（如架构师、前端专家、测试员、安全专家等）。这些 Agent 之间可以互相

通信、协作解决依赖问题，类似于人类开发团队的敏捷工作流。



**pipeline**

流水线模式，按步骤顺序执行。



适合对流程控制有严格要求的任务，或者需要分阶段验证结果的场景（例如：先设计架构 -> 再编写代码 -> 最后运行测试）。

任务会被拆分成明确的阶段，前一个阶段完成后才会触发下一个阶段，确保每一步都符合预期。





**eco**

经济模式，节省 Token 成本。



OMC 会智能选择更轻量级的模型（如 Claude Haiku）来处理子任务，仅在必要时才调用强大的模型（如 Opus），从而在保证完成任务

的前提下，最大限度地降低 API 使用成本（据称可节省 30-50% 的 Token）。



- Haiku：简单任务、代码搜索、文档查询
- Opus：复杂推理、架构设计、疑难调试



**ralph** 

启用持久执行，长任务不容易中途停。



## 使用案例

```
ralph swarm:帮我写个新的前后端项目，功能为：个人记账。
开发好后自己测试下，没问题后打开浏览器让我试试。
```



# 内置Agent

## Agent分类

插件内置了 32 个专业 Agent，覆盖：

- **架构类**：架构设计、技术选型、性能分析
- **研究类**：技术调研、竞品分析、最佳实践查找
- **开发类**：前后端开发、数据库设计、API 设计
- **测试类**：单元测试、集成测试、端到端测试
- **数据类**：数据分析、可视化、机器学习



## Agent召唤

在 **Swarm 模式** 下，你可以显式地“点名”让某个特定领域的专家介入。这比泛泛而谈更有效。

| 魔法关键词                | 召唤角色       | 作用                                       |
| :------------------------ | :------------- | :----------------------------------------- |
| **`@architect`**          | 系统架构师     | 负责整体结构设计、技术选型、模块划分。     |
| **`@coder`** / **`@dev`** | 高级开发工程师 | 专注于具体代码实现、算法优化。             |
| **`@tester`** / **`@qa`** | 测试专家       | 编写单元测试、集成测试，寻找边界情况 Bug。 |
| **`@security`**           | 安全审计员     | 检查代码漏洞、依赖风险、注入攻击等。       |
| **`@uiux`**               | UI/UX 设计师   | 优化前端样式、用户体验、无障碍访问。       |
| **`@docs`**               | 文档专家       | 生成 README、API 文档、代码注释。          |
| **`@debugger`**           | 调试专家       | 专门分析报错日志，定位深层问题。           |

案例

```
# 案例1：在 Swarm 模式下，专门叫安全专家来审查刚才写的代码
"@security please review the authentication module for vulnerabilities."


# 案例2
"我要构建一个电商后台。@architect 先设计数据库和微服务架构；@coder 和 @uiux 并行开发核心模块；@security 全程监控代码安全。如果遇到分歧，请 /debate 解决。"
```
