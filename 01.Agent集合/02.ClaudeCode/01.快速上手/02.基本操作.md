# 模式切换

**默认模式**

- 行为：修改文件前必须经过你确认（Yes/No）。
- 适用：日常开发，最安全，推荐默认使用。



**/plan**

```
/plan 帮我开发一个二手交易平台。
```

自动：自动编辑，无需申请权限。

让 Claude 只读分析代码库，制定详细的实施计划，而不立即修改任何文件。



工作流程：

1. 分析：Claude 会读取相关文件，理解现有架构。
2. 输出计划：它会生成一个分步骤的计划（例如：1. 修改文件 A；2. 新增文件 B；3. 更新测试用例）。
3. 用户确认：你检查计划，提出修改意见（例如：“第二步不需要改数据库”）。
4. 执行：计划确认后，你可以让它开始执行（通常切换回默认模式或直接说“开始执行”）。





**/fast**

快速生成代码或执行简单任务。它牺牲了一定的严谨性来换取速度。

```
/fast 帮我开发一个二手交易平台。
```



特点

- 少确认：对于小的修改，可能不会每次都停下来问你“是否确认修改”。
- 直给代码：减少长篇大论的分析，直接输出结果。
- 适合小任务：重命名、写一个简单的脚本、解释一小段代码。

# ！运行bash命令

claude交互下执行bash命令。

```
!bash命令

!pwd
```



**后台运行**

执行完bash命令后，根据提示输入ctrl+b让bash命令进入后台运行。

可以通过/task查看和管理后台任务。



**&方式**

```
! bash -lc 'i=1; while [ $i -le 120 ]; do printf "tick %s\n" "$i"; i=$((i+1)); sleep 5; done' &
```

通过在bash命令后加&的方式，可以让命令在后台运行。

但是无法被claude code进行管理(/tasks)。

# ctrl+g

把当前输入内容放到你的默认编辑器里改。

  它有什么用

  - 终端里写长 prompt 不方便
  - 多段内容、分点说明、粘贴大段文本时容易乱
  - 所以 Ctrl+G 会调用 $EDITOR，让你在熟悉的编辑器里编辑，再回到 Claude Code

  $EDITOR 是什么

  - 它是系统环境变量，表示你的默认编辑器
  - 常见例子：
    - vim
    - nvim
    - nano
    - code --wait
    - cursor --wait

  你怎么用

    1. 在 Claude Code 输入框里先写一点内容，或者直接准备写长需求
    2. 按 Ctrl+G
    3. Claude Code 会打开 $EDITOR
    4. 你在编辑器里把内容写完整
    5. **保存**并**关闭**编辑器
    6. 回到 Claude Code，内容会回填到输入区
    7. 你再按回车发送

  给你一个具体案例
  比如你想发一个很长的需求：

  - 修改登录逻辑
  - 增加审计日志
  - 保留旧接口兼容
  - 最后跑测试并告诉我影响范围

  这种在终端里直接敲很难整理。
  这时你按 Ctrl+G，会进入编辑器，写成：

  - 修复登录逻辑中的 token 刷新问题
  - 增加登录成功/失败审计日志
  - 保持旧接口参数兼容
  - 修改后运行相关测试
  - 最后总结改动文件和风险点

  保存退出后，这整段就会回到 Claude 输入框里，你再发出去。

  常见注意

  - 如果 $EDITOR 没设置，Ctrl+G 可能没反应或报错
  - 如果你用的是 VS Code / Cursor，最好配 --wait
    - 例如：code --wait
    - 否则 Claude 可能来不及等你编辑完
  - 有些终端会拦截快捷键，导致不生效

  一句话记忆

  - Ctrl+G = “去外部编辑器里认真写，再带回来”



# Ctrl+R

按 `Ctrl+R` 交互式搜索您的命令历史：

- **开始搜索**：按 `Ctrl+R` 激活反向历史搜索
- **键入查询**：输入文本以在以前的命令中搜索 - 搜索词将在匹配结果中突出显示
- **导航匹配**：再次按 `Ctrl+R` 循环浏览较旧的匹配
- 接受匹配
  - 按 `Tab` 或 `Esc` 接受当前匹配并继续编辑
  - 按 `Enter` 接受并立即执行命令













# ctrl+t

可以，我用一个**很具体的场景**给你讲 `Ctrl+T`。

- `Ctrl+T = toggle tasks`
- `toggle` 就是“开/关切换”
- `tasks` 就是 Claude 当前这次工作拆出来的任务列表/进度面板

**你可以把它理解成**
- 平时：你看到的是聊天输入界面
- 按一次 `Ctrl+T`：切到“任务视图”
- 再按一次 `Ctrl+T`：切回聊天界面

**案例**
假设你对 Claude 说：

- `帮我排查登录接口 500 错误，修复后再跑测试`

这时 Claude 往往会把工作分成几步，比如：

- 定位报错位置
- 修改接口逻辑
- 运行相关测试
- 总结结果

这时候你按 `Ctrl+T`，通常就会看到类似这样的任务面板：

- `定位报错位置` `completed`
- `修改接口逻辑` `in_progress`
- `运行相关测试` `pending`
- `总结结果` `pending`

你不用盯着聊天窗口猜“它现在在干嘛”，直接看任务面板就知道：
- 哪一步做完了
- 现在卡在哪一步
- 后面还剩什么

**它有什么用**
- Claude 在做多步任务时，你能快速看进度
- 跑测试、改多处代码、长时间分析时特别有用
- 比一直翻聊天记录更直观

**什么时候你会觉得“没反应”**
- 只是普通闲聊，没有任务拆分
- 当前这次工作没有可显示的任务
- 终端/界面不支持或拦截了按键

所以如果你刚刚只是问一句：
- `你好`
- `你是谁`
- `最近最火的AI技术`

这类场景按 `Ctrl+T`，可能看不到什么，因为根本没有任务列表可切换。

**一句话版**
- `Ctrl+T` 不是“执行任务”
- 它是“查看/隐藏任务进度面板”
