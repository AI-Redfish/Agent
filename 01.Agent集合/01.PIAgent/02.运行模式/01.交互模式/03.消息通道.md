# 消息通道

> 交互模式下，Agent 正在干活时你依然可以输入消息。这些消息不会打断当前执行，而是进入**消息队列（Message Queue）**，通过两条不同的通道在合适的时机投递给模型。

# 两条消息通道

| 通道 | 默认按键 | Windows/WSL 按键 | 投递时机 |
| :--- | :------- | :--------------- | :------- |
| **Steering（转向消息）** | Enter | Enter | 当前 assistant 回合**执行完工具调用后**立即投递，Agent 继续工作 |
| **Follow-up（后续消息）** | Alt+Enter | **Ctrl+Q** | Agent **完成全部工作后**才投递 |

两条通道的区别一句话理解：

- **Steering 是"中途纠偏"**：Agent 还在干活，你有新的指示要插进去 → 等它做完手上这一轮工具调用就送达
- **Follow-up 是"排队追加"**：不干扰当前任务，等它彻底忙完再说

**典型用法**

```
（Agent 正在重构代码...）
别用方案 A 了，改用方案 B 实现     ← Enter，steering，下一轮工具调用前送达

（Agent 正在写代码...）
写完后顺便把测试也跑一遍           ← Ctrl+Q，follow-up，全部完成后再投递
```



**队列管理**

| 按键 | Windows/WSL 按键 | 功能 |
| :--- | :--------------- | :--- |
| Escape | Escape | 中止当前执行，并把队列中的消息恢复到编辑器 |
| Alt+Up | **Alt+Q** | 把队列中的消息取回编辑器（不中止执行） |

# 投递模式配置

Steering 和 Follow-up 各自支持两种投递模式，通过 `/settings` 面板（消息传递分区）或 settings.json 配置：

| 设置项 | 默认值 | 可选值 | 说明 |
| :----- | :----- | :----- | :--- |
| `steeringMode` | `"one-at-a-time"` | `"one-at-a-time"` / `"all"` | steering 消息的投递方式 |
| `followUpMode` | `"one-at-a-time"` | `"one-at-a-time"` / `"all"` | follow-up 消息的投递方式 |

**两种模式区别**：

- `one-at-a-time`（默认）：每次只投递一条，**等模型响应后**再投递下一条
- `all`：把队列中的消息**一次性全部**投递给模型

配置示例（~/.pi/agent/settings.json 全局，或项目 .pi/settings.json）：

```json
{
  "steeringMode": "all",
  "followUpMode": "one-at-a-time"
}
```
