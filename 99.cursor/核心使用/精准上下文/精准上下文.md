在Cursor 工具里，“上下文(Context)“可理解为 让 AI 准确理解需求、辅助编码的“信息参考范围”，是Al读懂代码、精准响应的关键!



# CodeBase Indexing代码库索引

打开项目时，每个Cursor 实例都将初始化该工作区的索引。

后续新增的文件回自动编制索引。



**代码库索引作用**：

快速“读懂” 你的项目结构(哪些是工具文件、哪些是业务逻辑)。

定位相关代码(如搜索 getUser 时，知道优先查 userservice.js)。

理解代码关系(如 order类和 Product类的关联)。

提升索引速度：排除大型依赖、生成文件(如 node_modules、dist)。

避免干扰：某些配置文件可能包含敏感信息或与当前任务无关。



**创建忽略配置文件**

有两种方式

1，自己创建.cursorignore 文件添加到代码库目录的根目录下，并列出要忽略的目录和文件。

2，使用cursor配置快捷创建忽路文件cursor setting>indexing> configure ignored files。







**添加忽略的文件**

```

# 忽略任意层级下的 temp/ 目录。效果和dir/	一致。
**/temp/	

# 不忽略（即保留）该文件，即使前面规则匹配了
!important.txt	
```



# Rules规则

Rules是给Cursor AI功能生成结果添加规则和限制，该规则适用于Chat和 Cmd K。

让 A1 生成的代码贴合团队规范，减少人工二次修改成本，主要的作用如下:



可约束代码风格(如强制用驼峰命名、要求函数必须写注释)。

能限定技术选型(如禁止使用某老旧库、优先用项目指定工具类)。

提前指定核心参数(如提前设置连接数据库的地址和账号密码等)。



Rule主要的配置方案有两种:
项目规则和用户规则。

项目规则和用户规则同时存在并且规则冲突，项目规则优先级更高。

| 维度     | 项目规则(Project Rules)                    | 用户规则(User Rules)            |
| -------- | ------------------------------------------ | ------------------------------- |
| 作用范围 | 仅对当前项目生效，团队成员共享相同规则     | 对所有项目生效，个人专属配置    |
| 存储位置 | 项目根目录下的.cursor/ru1es/随意.mdc文件   | 用户配置目录(如~/.cursor/rules) |
| 同步方式 | 随项目代码提交到版本库(如 Git)，团队共享   | 仅本地生效，不随项目同步        |
| 适用场景 | 统一团队编码规范(如函数注释格式、依赖版本) | 个人习惯(如快捷键、AI 响应风格) |



## **项目规则-文件创建**

1，创建文件夹自定义文件：   项目/.cursor/rules/随意命名.mdc

2，快捷命令方式创建 cmd + shift +P>“New Cursor Rule”



建议使用命名约定如 NNN_name.mdc（NNN 为 001-299，代表优先级）。



## 项目规则-模式

| 模式                              | 介绍                                             | 使用场景                                                     |
| --------------------------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| Always applied                    | 始终应用规则                                     | 定义每个规则、每个方法类都必须写注释                         |
| Apply to Specific Files & Folders | 当匹配 `globs` 模式的文件时，自动附加规则        | 制定触发的[文件类型](https://so.csdn.net/so/search?q=文件类型&spm=1001.2101.3001.7020)，比如所有的js文件会触发这个规则 ，那配置就是*.js（前后端规则区分） |
| Agent Requested                   | 根据 Agent需求决定是否应用规则，需要提供规则说明 | 通过自然语言，AI自己决定是否使用                             |
| Manual                            | 仅在提示中显式使用 `@规则名` 时附加规则          | 特殊场景，用户手动使用规则                                   |

````

globs: src/java/*
versions: 1.0.1
last_updated: 2025-11-01
---

# java开发规则

## 上下文
上下文使用springboot3，maven3，mysql，mybatis-flex,minio,redis，xxjob等技术栈。

## 规则
- 文件名称和类名一致。
- 优先使用for循环，而不是stream。
- 方法尽可能保持通用性。
- 测试文件需包含 @testing-library/react</code>

## 格式
- 保持一致的缩进和间距。
- 遵循标准命名约定。

## 实例
```

import java.util.stream.Stream;
public class Demo {


    // 写一个工具方法，计算数组平均值
    public static double average(int[] array) {
        int sum = 0;
        for (int i = 0; i < array.length; i++) {
            sum += array[i];
        }
        return (double) sum / array.length;
    }

   
}
```

Cursor的 MDC(Markdown with Cursor)语法是专门为编写项目规则设计的轻量级格式，它结合了 Markdown的可读性和元数据配置能

力。接下来，我们来说明下mdc文件语法。





**前置元数据（Frontmatter）**

使用 --- 包裹，包含以下字段：

description：规则的简要描述，指导AI何时应用该规则。例如“前端开发规则”。

globs：指定规则生效范围(支持glob语法)。例如 ".ts" 或 "src/components/"，或"src/**/*.{js,ts,jsx}"。

priority：规则优先级，数值越大优先级越高，解决规则冲突。示例：100



以上为官方字段，也可以添加自定义字段如下：

author：作者姓名。

version（版本号，如 1.0.0）

last_updated（最后更新日期，如 2025-03-11）。



**常见规则内容**

```
你是一个专业的 Java 开发助手，遵循以下项目规则：

#技术栈
- Java 版本：Java 11 或 Java 17（LTS）
- 框架：Spring Boot 3.x + Spring MVC + Spring Data JPA / MyBatis
- 构建工具：Maven 或 Gradle
- 数据库：MySQL 8.0 / PostgreSQL / Oracle
- ORM：JPA + Hibernate / MyBatis-Plus
- 接口文档：Swagger/OpenAPI 或 SpringDoc
- 缓存：Redis + Spring Data Redis
- 消息队列：RabbitMQ / Kafka
- 安全：Spring Security + JWT
- 日志：SLF4J + Logback
- 单元测试：JUnit 5 + Mockito

# 代码风格
- 遵循 Google Java Style Guide
- 缩进：4 个空格
- 大括号换行（K&R 风格）
- 类名：PascalCase，方法名：camelCase，常量：UPPER_SNAKE_CASE
- 所有类和公共方法必须有 Javadoc 注释
- 使用 Lombok 时，合理使用 @Data、@Builder、@NoArgsConstructor、@AllArgsConstructor
- 实体类必须实现 Serializable
- 使用 Optional<T> 避免 null 返回
- 异常处理：使用 @ControllerAdvice + @ExceptionHandler 统一处理
- 返回 JSON 格式统一为：
  { "code": 200, "data": null, "message": "success" }

# 安全约束
- 绝对禁止硬编码密码、密钥、数据库连接信息
- 所有用户输入必须校验（使用 @Valid + Bean Validation）
- 防止 SQL 注入：使用 JPA 参数化查询或 MyBatis #{} 语法
- 防止 XSS：输出时转义 HTML 特殊字符
- JWT 必须设置过期时间，使用 HS512 或 RS256 算法
- 敏感接口必须加 @PreAuthorize 或权限校验
- 禁止使用 System.out.println()，改用 LoggerFactory.getLogger()

# 项目结构理解
- /src/main/java/com/example/...: Java 源码
- /src/main/resources: 配置文件（application.yml、mapper/*.xml）
- /src/test: 单元测试
- /src/main/resources/static: 静态资源（可选）
- /src/main/resources/templates: 模板文件（Thymeleaf）
- pom.xml 或 build.gradle：构建配置
- application.yml: 主配置文件

请始终以专业、安全、可维护的方式生成 Java 代码。
```

## @Terminal

在与 AI 对话时将终端（Terminal）的输出内容自动注入到当前对话上下文中，让 AI 能“看到”你最近运行的命令及其结果。



假设你运行了一个命令但报错了：

```
$ npm run build
Error: Cannot find module 'react'
```

此时你在 Cursor 的聊天框里输入：

```
@Terminal 为什么构建失败？
```

👉 Cursor 会自动：

1. 读取你**最近一次在集成终端中执行的命令和输出**；

2. 把这段错误信息作为上下文提供给 AI；

3. AI 就能基于真实错误（如缺少 

   ```
   react
   ```

    模块）给出精准回答，比如：

   > “你没有安装 react 依赖，请运行 `npm install react`。”

而**不需要你手动复制粘贴错误信息**！



**三种terminal**

|                          | 是什么                                                       | 案例                                                         |
| ------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `@Terminal (Cursor)`     | 在 Cursor 底部直接打开的 **主终端面板**                      | 手动在cursor的底部terminal执行npm install 报错后。@Terminal 为什么 npm install 报错？ |
| `@Terminal (PowerShell)` | 如果你在 **Windows 系统**上，并且 Cursor 检测到你使用的是 **PowerShell 作为默认 shell**，它会单独标记这个上下文。<br />功能上和 `@Terminal (Cursor)` 几乎一样，只是**明确标识了 shell 类型**，便于 AI 更准确理解命令语义。 |                                                              |
| `@Terminal (Agent)`      | 这是 **Agent 模式运行时内部使用的隔离终端会话**，用于执行它自动生成的命令（如运行测试、安装依赖、启动服务等）。所有命令由 AI 自动发出，**非用户手动操作**。 | 例如，在 Agent 卡住时，你可以问：text@Terminal (Agent) 为什么测试一直失败？→ AI 会查看 Agent 自己运行 npm test 的输出，并调整策略。 |

## @Past Chats

> **让当前 AI 对话能“看到”你之前与 Cursor 的聊天记录（尤其是近期的相关对话），从而保持上下文连贯、避免重复解释。**

当你输入 `@Past Chats` 并发送消息时，Cursor 会：

1. 自动检索你**在当前项目中最近的几次对话历史**；
2. 将这些聊天内容作为**附加上下文**提供给 AI；
3. AI 基于**完整对话脉络**给出更精准、连贯的回答。



**场景 1：继续中断的任务**

- 昨天你让 Agent 添加用户登录功能。

- 今天你输入：

  ```
  @Past Chats 继续完成登录功能的测试用例
  ```

- AI 会回忆起你昨天的计划（如“已创建表单和路由，还差 JWT 验证”），直接接着做。



**场景 2：避免重复描述**

- 你之前详细解释过某个业务逻辑（比如“订单状态机有 pending → paid → shipped”）。

- 现在想问：

  ```
  @Past Chats 如何为这个状态机加超时取消？
  ```

- AI 不需要你再重复状态定义，直接基于已有上下文设计方案。



**场景 3：调试延续**

- 之前用 `@Terminal` 调试了一个构建错误，AI 建议升级 Node.js。

- 现在你升级后仍报错，可以问：

  ```
  @Past Chats 升级 Node 后还是报同样的错，怎么办？
  ```

- AI 知道“同样的错”指的是什么，无需你贴日志。



## @Branch

将当前 Git 仓库的分支状态（如分支名、提交历史、差异等）注入到 AI 的上下文中，使 AI 能基于分支语义提供更精准的建议或操作。

当你在聊天中使用 `@Branch`，Cursor 会自动：

1. 检测你当前所在的 **Git 分支（如 `feature/login`、`main`）**；
2. 获取该分支与目标分支（通常是 `main` 或 `develop`）之间的 **代码差异（diff）**；
3. 将这些信息作为上下文提供给 AI。

这样，AI 就能理解：“你正在开发什么功能”、“改了哪些文件”、“和主干有什么不同”。



**场景 1：生成 Pull Request 描述**

```
@Branch 写一个专业的 PR 描述，总结本次改动。
```

→ AI 会分析 `feature/login` 分支相对于 `main` 的所有变更，自动生成：

- 新增功能
- 修改点
- 可能的影响



**场景 2：审查自己的代码**

```
@Branch 这个分支的实现有没有潜在 bug 或安全问题？
```

→ AI 会重点审查 **本次分支新增/修改的代码**，而不是整个项目。



**场景 3：切换上下文时快速同步**

你刚切到一个同事的分支 `fix/api-timeout`，直接问：

```
@Branch 这个分支在修什么问题？需要我做什么？
```

→ AI 解读 diff 后告诉你：“在修复 API 超时未处理的问题，已添加 retry 逻辑，但缺少单元测试。”



**场景 4：准备合并前的检查**

```
@Branch 在合并到 main 前，有哪些需要注意的地方？
```

→ AI 可能提示：“你修改了核心 utils，记得更新文档；另外有 2 个新依赖未加到 package.json。”



## @Browser

当你使用 `@Browser` 时，Cursor 会：

1. **自动检测你最近访问的网页**（通过本地集成或权限授权）；
2. **提取页面的关键内容**（如标题、正文、代码示例、错误信息）；
3. 将这些内容注入到与 AI 的对话上下文中；
4. AI 基于**你正在看的网页 + 项目代码** 给出精准回答。



**场景 1：结合官方文档提问**

你在浏览器打开了 [React 官方文档 - useEffect](https://react.dev/reference/react/useEffect)，然后在 Cursor 中问：

```
@Browser 这个 useEffect 的清理函数怎么写才不会内存泄漏？
```

→ AI 会参考你刚看的文档内容，给出符合最新 React 规范的示例。



**场景 2：调试 Stack Overflow 或错误页面**

你在浏览器看到一个报错：

> ```
> TypeError: Cannot read property 'map' of undefined
> ```

同时打开了一个 Stack Overflow 帖子。你问：

```
@Browser 根据这个错误和解决方案，怎么改我的代码？
```

→ AI 会结合错误原因 + 社区答案 + 你的项目结构，生成修复建议。



**场景 3：快速理解第三方库用法**

你正在看 [Axios GitHub README](https://github.com/axios/axios)，想在项目中用它发请求：

```
@Browser 根据这个文档，帮我写一个带拦截器的 Axios 实例。
```

→ AI 直接基于你浏览的文档生成符合规范的代码。
