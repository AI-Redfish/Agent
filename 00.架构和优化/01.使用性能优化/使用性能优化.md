# 概述
Agent，如claude code等使用过程中，会出现任务执行过长的情况。
本文介绍如何排查性能问题，并提升claude code等Agent执行效率。


# 模型降智
- 如果使用中转站等平台，模型可能会被降智。
- 后台查看推理强度，是否从 high 降为 medium。

# 缓存
高缓存命中率可以提升对话性能，也能避免Agent健忘。

解决方案如下：
- Agent客户端升级到最新版本。如claude code旧版本存在缓存bug。
- 自定义Agent客户端缓存策略。需要较高的修改成本。

# 会话记忆过载
工作空间不变的情况下，长期记忆文件会越来越臃肿，导致AI对话负重前行。

解决方案如下：
- /clear 清空会话记忆。
- 清空长期记忆文件。
- 使用git worktree克隆新的工作空间，保证上下文干净。

# subAgent
SubAgent（子代理）是解决任务耗时长的核心工具。
用多个并行的上下文窗口来执行任务，主对话负责拆分和协调，SubAgent 独立执行子任务。


# 多余任务
很多性能问题不是模型慢，而是它在做不该做的事。如针对用户任务过度发散，执行不需要的操作。


## 先想后做
先让Agent客户端用计划模式，输出计划，任务清单等。然后再执行具体任务。
避免Agent做不必要的事情。

## 避免不必要的skill或插件
skill过多或有些插件会将任务复杂化。
- superPowers会对每一个任务进行规划，开发，代码审查，单元测试等。

如果不是特别复杂，尽量避免使用superPowers等插件，也要避免skill或者其他工具过多。

# 上下文管理
当对话越来越长，Agent会变得迟钝。

需及时清空或者压缩会话。

- /clear 清空会话。
- /compact 压缩会话
如果可以，尽量清空会话，保证上下文干净。



# 多Agent并行
如使CCCP（Claude Code Concurrent Processor）创建多个claude code会话来将任务拆解后并行执行。

拆分任务遵循如下建议：


## 合适的模式

如CCCP有两种模式：

**API模式**

速度最快，适合不需要读写本地文件的分析类任务。

**CLI模式**
需要实际修改代码、运行命令的任务

## 合理的并发
默认 8 通常够用。API 有速率限制，设置过高反而会触发限流。

## 任务粒度
每个子任务应该在 30-60 秒 内完成。如果某个任务明显更耗时，考虑进一步拆分。

## 明确依赖关系

明确各任务依赖关系，避免结果错乱。

## 配合planMode
与 Plan Mode 配合：先用 Plan Mode 制定整体方案，确认任务可以安全并行拆分，再用 CCCP 执行。
