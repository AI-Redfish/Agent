# 短期记忆

## Checkpointer

短期记忆页的核心是：用 `Checkpointer` 保存线程级状态，让多轮对话延续上下文。


**使用**

```python
from langgraph.checkpoint.memory import InMemorySaver

checkpointer = InMemorySaver()

agent = create_agent(
    model=model,
    tools=[],
    checkpointer=checkpointer
)
```


## thread_id

`thread_id` 用来区分不同会话线程。


**使用**

```python
config = {"configurable": {"thread_id": "user-001"}}

agent.invoke({"messages": [{"role": "user", "content": "我叫小明"}]}, config=config)
agent.invoke({"messages": [{"role": "user", "content": "我叫什么？"}]}, config=config)
```


## 常见记忆策略

短期记忆页重点提到：

- 截断消息
- 删除消息
- 总结消息
- 自定义记忆策略


**理解**

- 上下文太长时不能无脑全塞
- 要在“保留关键上下文”和“控制 token 成本”之间平衡


# 长期记忆

## Store

长期记忆页强调跨会话持久化数据，通常用 Store 保存。


**使用**

```python
store.put(("preferences",), "language", "中文")
item = store.get(("preferences",), "language")
```


## 典型内容

- 用户偏好
- 长期画像
- 已确认的业务信息
- 跨线程共享配置


## Checkpointer vs Store

| 能力 | 用途 | 生命周期 |
| :-- | :-- | :-- |
| Checkpointer | 保存会话线程状态 | 单线程 |
| Store | 保存长期记忆 | 跨线程 / 跨会话 |


# 人工介入

## interrupt()

人工干预页的核心是：在关键节点中断执行，等待人工审批、编辑或补充。


**使用**

```python
from langgraph.types import interrupt

@tool
def approve_refund(order_id: str) -> str:
    decision = interrupt({"order_id": order_id, "action": "approve_refund"})
    return f"审批结果：{decision}"
```


## 决策类型

官方页重点列出：

- approve
- reject
- edit
- respond


## 适合场景

- 支付
- 退款
- 删除数据
- 发邮件
- 修改生产配置


# 多 Agent

## 为什么使用多 Agent

多 Agent 适合把复杂任务拆给多个专门角色处理，降低单 Agent 负担。


## 常见模式

### 子代理

把专门能力封装成子代理，主代理像调用工具一样调用。


**适合**

- 研究员 Agent
- SQL Agent
- 检索 Agent
- 审核 Agent


### Handoffs

交接模式适合“主导权切换”，由一个 Agent 把会话接力给另一个 Agent。


**适合**

- 客服分流
- 售前转售后
- 普通支持转专家支持


### Skills

技能模式适合按需加载一组固定能力，而不是把所有能力都塞进主 Agent。


### Router

路由模式用于把请求分发到不同知识域、不同数据源或不同专家 Agent。


### Custom Workflow

自定义工作流适合强控制流程，例如固定顺序执行检索、分析、汇总。


## 选择建议

| 模式 | 适合场景 |
| :-- | :-- |
| 子代理 | 主 Agent 调多个专家工具 |
| Handoffs | 会话控制权切换 |
| Skills | 能力按需挂载 |
| Router | 多领域分流 |
| Custom Workflow | 固定业务流程 |


**建议**

- 先把单 Agent 做清楚，再考虑多 Agent
- 职责边界要清晰
- 多 Agent 一定要配状态管理和 tracing
