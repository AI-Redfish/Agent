# 学习目标

## 本篇目标

本篇说明 LangGraph 如何暂停执行、等待人工输入，再从原位置恢复。理解这一篇前，最好先掌握 checkpointer 和 `thread_id`。

# Human-in-the-loop

## 基本概念

Human-in-the-loop 指在 Agent 执行过程中让人参与决策。LangGraph 通过 interrupt 和 checkpoint 支持这种模式。

常见场景：

- 工具调用前需要人工确认。
- 发送邮件、提交订单、删除数据前需要审批。
- Agent 生成计划后等待用户选择。
- 自动化流程遇到低置信度结果，需要人工判断。
- 敏感操作需要二次确认。

## 为什么需要中断

普通函数调用一般是一次性执行完。但真实 Agent 经常需要暂停：

```text
Agent 生成方案
  -> 暂停等待用户确认
  -> 用户确认或修改
  -> Agent 继续执行
```

这要求系统能保存执行状态，并在用户回复后从原位置恢复。

# Interrupt

## interrupt 的作用

`interrupt()` 用于暂停图执行，并把需要用户处理的信息返回给调用方。

示意：

```python
from langgraph.types import interrupt


def ask_human(state):
    human_input = interrupt({
        "question": "是否继续执行这个操作？",
        "draft": state["draft"],
    })
    return {"human_decision": human_input}
```

当执行到 `interrupt()` 时，图会暂停。调用方拿到中断信息后，可以展示给用户。

## interrupt 依赖 checkpointer

中断恢复必须依赖 checkpointer。因为 LangGraph 需要知道：

- 暂停在哪个节点。
- 当前 state 是什么。
- 恢复后从哪里继续。

编译时需要：

```python
from langgraph.checkpoint.memory import InMemorySaver

checkpointer = InMemorySaver()
graph = builder.compile(checkpointer=checkpointer)
```

调用时需要稳定的 `thread_id`：

```python
config = {"configurable": {"thread_id": "approval-001"}}
```

# Resume

## Command(resume=...)

用户给出反馈后，通过 `Command(resume=...)` 恢复图执行。

示意：

```python
from langgraph.types import Command

result = graph.invoke(
    Command(resume={"approved": True}),
    config=config,
)
```

恢复后，`interrupt()` 的返回值就是 `resume` 传入的内容。

## 审批流示例

流程：

```text
generate_plan
  -> human_approval interrupt
  -> approved: execute_plan
  -> rejected: revise_plan
```

示意代码：

```python
def human_approval(state):
    decision = interrupt({
        "type": "approval",
        "plan": state["plan"],
        "message": "请确认是否执行该计划",
    })
    return {"approved": decision["approved"]}
```

路由：

```python
def route_after_approval(state):
    if state["approved"]:
        return "execute_plan"
    return "revise_plan"
```

# 设计模式

## 工具调用前审批

适合高风险工具：

- 删除文件。
- 修改数据库。
- 发送通知。
- 调用支付接口。
- 发布内容。

流程：

```text
agent_decide_tool
  -> interrupt 请求审批
  -> approved 执行工具
  -> rejected 让 Agent 重新规划
```

## 计划确认后执行

适合复杂任务：

```text
analyze_requirement
  -> generate_plan
  -> interrupt 等用户确认
  -> implement
  -> verify
```

这样可以避免 Agent 在需求不清楚时直接动手。

## 人工补充信息

当 Agent 缺少必要信息时，可以 interrupt：

```text
missing_required_info
  -> ask_human
  -> resume with answer
  -> continue
```

这比让 Agent 瞎猜更可靠。

# 审批数据结构

## 推荐结构

人工审批建议使用结构化数据：

```python
{
    "approved": True,
    "comment": "同意执行",
    "edited_plan": None
}
```

如果用户可能修改方案，可以传：

```python
{
    "approved": False,
    "comment": "需要先补测试",
    "edited_plan": "先补单测，再修改实现"
}
```

后续节点根据字段判断，而不是解析自然语言。

# 常见问题

## 没有 checkpointer

没有 checkpointer 时，interrupt 无法可靠恢复。

学习阶段：

```python
InMemorySaver()
```

生产环境：

```text
PostgreSQL / MongoDB / Redis / SQLite
```

## thread_id 不稳定

恢复必须使用同一个 `thread_id`。如果第一次调用和 resume 时 thread_id 不同，LangGraph 找不到之前暂停的状态。

## interrupt 中做副作用

不要在 interrupt 前后混杂不可重复的副作用。

不推荐：

```python
def node(state):
    charge_money()
    decision = interrupt("是否继续？")
    return {}
```

推荐：

```text
先 interrupt 审批
审批通过后再执行副作用
```

## resume 数据结构不清晰

`resume` 最好传结构化对象：

```python
Command(resume={"approved": True, "comment": "同意执行"})
```

不要只传模糊字符串，后续节点难以稳定解析。
