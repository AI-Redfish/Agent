# 学习目标

## 本篇目标

本篇解释 LangGraph 的记忆和持久化机制。重点区分短期记忆、长期记忆、checkpointer、thread 和 memory store。

# 记忆类型

## 短期记忆

短期记忆通常指“同一个会话线程中的上下文”。在 LangGraph 中，它常由 checkpointer 保存。

典型特点：

- 以 `thread_id` 区分不同会话。
- 保存图执行过程中的状态快照。
- 适合聊天历史、当前任务进度、临时上下文。
- 用户下一轮继续对话时，可以恢复之前状态。

## 长期记忆

长期记忆通常指跨会话、跨线程保存的信息。

适合保存：

- 用户偏好。
- 长期事实。
- 项目知识。
- 可复用经验。
- 业务实体信息。

长期记忆不应该等同于完整聊天历史。它更像经过筛选和整理后的知识库或 key-value store。

# Checkpointer

## 基本作用

Checkpointer 用来保存图执行状态。它是 LangGraph 支持持久化、恢复、中断、人机协作的重要基础。

常见能力：

- 保存每一步 state snapshot。
- 根据 `thread_id` 恢复会话。
- 支持 interrupt 后 resume。
- 支持 time travel 或回看历史状态。
- 支持故障恢复。

## InMemorySaver

学习阶段常用内存版 checkpointer：

```python
from langgraph.checkpoint.memory import InMemorySaver

checkpointer = InMemorySaver()
graph = builder.compile(checkpointer=checkpointer)
```

调用时传入配置：

```python
config = {"configurable": {"thread_id": "user-001"}}
result = graph.invoke(input_data, config=config)
```

同一个 `thread_id` 会恢复同一条会话线程。

# Thread

## thread_id

`thread_id` 是 LangGraph 区分不同会话的关键。

示例：

```python
config = {"configurable": {"thread_id": "chat-123"}}
```

同一个用户的同一段会话应该使用稳定的 `thread_id`。

不同用户或不同任务应该使用不同的 `thread_id`。

## 使用建议

建议命名方式：

```text
user:{user_id}:chat:{conversation_id}
user:{user_id}:task:{task_id}
project:{project_id}:agent:{agent_id}
```

不要把所有请求都用同一个 `thread_id`，否则会话状态会互相污染。

# Persistence

## 状态快照

持久化保存的是图执行过程中的状态快照。每次节点执行后，LangGraph 可以保存当前状态。

这带来几个能力：

- 当前请求失败后可以恢复。
- 人工审批时可以暂停。
- 下一轮对话可以继续。
- 可以检查中间状态。

## 生产环境存储

学习阶段可以用 `InMemorySaver`，生产环境应该使用持久化后端，例如：

- SQLite。
- PostgreSQL。
- MongoDB。
- Redis。
- 云厂商存储。

选择建议：

| 场景 | 推荐 |
|---|---|
| 本地学习 | InMemorySaver |
| 本地开发 | SQLite |
| 生产服务 | PostgreSQL / MongoDB |
| 高并发缓存型场景 | Redis |
| 云原生架构 | 云厂商托管存储 |

# Memory Store

## 与 checkpointer 的区别

Checkpointer 和 memory store 不是一回事：

| 能力 | Checkpointer | Memory Store |
|---|---|---|
| 作用 | 保存图执行状态 | 保存长期记忆 |
| 生命周期 | 通常围绕 thread | 可跨 thread / user / project |
| 内容 | state snapshot | 用户偏好、事实、知识 |
| 用途 | 恢复执行、人机中断 | 个性化、长期上下文 |

## 设计建议

长期记忆建议经过筛选后再写入：

- 不要把每轮对话原样塞进去。
- 不要保存敏感信息，除非有明确授权和安全措施。
- 记忆要可更新、可删除。
- 记忆最好带来源和时间。
- 检索出来的记忆要作为上下文，而不是无条件信任。

# 会话示例

## 连续对话

同一个 `thread_id` 可以让图在下一轮调用时恢复之前状态：

```python
config = {"configurable": {"thread_id": "chat-001"}}

graph.invoke({"messages": [{"role": "user", "content": "我叫小明"}]}, config=config)
graph.invoke({"messages": [{"role": "user", "content": "我叫什么？"}]}, config=config)
```

如果 messages 字段配置了追加 reducer，第二次调用时可以读取到前一轮历史。

# 常见问题

## 忘记传 config

如果编译时用了 checkpointer，但调用时没有传 `thread_id`，就无法稳定恢复会话。

推荐：

```python
config = {"configurable": {"thread_id": thread_id}}
graph.invoke(input_data, config=config)
```

## 混淆短期记忆和长期记忆

短期记忆解决“这轮会话怎么继续”。

长期记忆解决“未来会话还要记得什么”。

两者应该分开设计。

## 生产环境使用内存存储

`InMemorySaver` 只适合学习和测试。服务重启后内存会丢失，不适合生产环境。
