

# 概述

OpenSpec 本质上是把需求整理成可执行规范：先说明要做什么、范围是什么、规则是什么、如何验收，再据此实现和测试。它适合需求容易变形、多人协作或 AI/Agent 参与的场景，核心价值是减少理解偏差和返工。

## 使用步骤

1. 先写目标，说明要解决什么问题、最终结果是什么。  
2. 再写非目标，明确这次不处理什么，避免范围失控。  
3. 接着写核心规则，把输入、输出、边界条件、异常情况说清楚。  
4. 最后写验收标准，明确怎么判断这件事算完成。  
5. 规范确定后，再按规范拆任务、写代码、补测试。

## 使用方式

常见写法很简单，一般包含 4 部分：目标、非目标、核心规则、验收标准。和直接写代码相比，它更强调先对齐“做成什么才算对”，再决定“怎么做”。

## 适用场景

适合新功能设计、流程改造、工具链接入、Agent 工作流编排这类任务。尤其在 AI 场景里，规范越清晰，生成结果越稳定，也更容易继续拆成设计、编码、测试等后续步骤。

## 简单模板

```md
# 功能名 / 规范名

## 目标
- 解决什么问题
- 最终效果是什么

## 非目标
- 这次不做什么

## 核心规则
- 当 ... 时，系统必须 ...
- 当 ... 不满足时，系统必须 ...

## 验收标准
- [ ] 功能符合预期
- [ ] 边界场景通过
```

## 总结

一句话理解：**先定义正确结果，再围绕规范实现。** 如果后续拿到视频字幕或要点，还可以继续补成更贴近视频内容的版本。
