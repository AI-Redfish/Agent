# Agent模式

## 整体流程

**输入**

一个高层次的、目标导向的任务描述。



**上下文获取**

进行全面的项目理解。AI 会像一个新入职的开发者一样，“阅读”整个项目结构，包括文件目录、依赖关系、代码风格等。



**AI处理-核心：自主代理循环**

Agent 模式的核心是一个 “思考-行动-观察-再思考” (Think-Act-Observe-Reflect) 的闭环循环。



1，规划 (Plan)：首先，它会像 `Plan` 模式一样，制定一个初步计划。

2，行动 (Act)：然后，它会自动执行（无需用户确认）计划中的第一步或几步。

3，观察 (Observe)：执行后，它会“观察”结果：

- 代码是否成功修改？
- 运行 `npm run test` 或 `flutter test`，检查测试是否通过？
- 运行 `npm run lint`，检查代码风格？
- 是否有编译错误？

4，再思考 (Reflect)：根据观察到的结果，Agent 会进行反思：

- 如果测试失败，它会分析失败原因，并生成修复代码。
- 如果发现需要额外的文件，它会自动创建。
- 如果第一步不成功，它会调整策略，尝试另一种方法。

迭代循环会持续进行，直到整个任务成功完成，或者遇到无法解决的问题而停止。



多轮交互：一个 Agent 任务可能涉及数十次甚至上百次的内部“思考-行动”循环。

自主决策：在整个过程中，不需要用户对每一步进行确认。它是一个“黑盒”式的自主代理。

# Plan模式



## 整体流程

**输入**

一个明确的、需要修改代码的任务指令。



**上下文获取**

Cursor 会自动对整个项目进行深入的上下文分析。

它会扫描当前文件、相关文件（如组件的 CSS 文件）、配置文件等，以理解任务的影响范围。



**步骤生成**

AI 将你的任务分解成一系列离散的、可执行的步骤。

AI 将这个完整的、逐步的计划清晰地展示在聊天窗口中。计划通常以有序列表或流程图的形式呈现。

如果AI针对你的问题有疑问，会想你提问，得到回答后会重新生成步骤。



**执行阶段**

执行暂停：在展示完计划后，AI 自动暂停，等待用户指令。

用户审查：你可以仔细检查每一步计划，确保它符合你的预期。

用户确认：只有当你明确输入 `Yes`、`Proceed` 或点击“继续”按钮后，AI 才会开始执行计划中的步骤。

执行过程：AI 会逐一执行计划，每完成一步可能会进行简短汇报。



# Debug模式

Debug 模式把“修 Bug”这件事变成了一个结构化、可验证、人机协作的流程，而不是过去那种“你描述一下错误，AI 直接改代码”的碰运气方式。



## **工作原理**

1. **你描述问题**
   例如：“刷新页面后游戏进度丢失” 或 “搜索结果大小写敏感，但 UI 显示不敏感”。
2. **AI 提出多个假设**
   基于代码上下文，AI 会列出可能出错的原因（比如：状态未持久化、并发更新冲突、函数逻辑错误等）。
3. **自动注入运行时日志（Runtime Logging）**
   AI 在关键代码位置**自动插入日志语句**（类似打桩），用于收集运行时数据。
4. **引导你复现问题**
   AI 会给出具体操作步骤（如：“点击分页 → 删除一条笔记 → 刷新页面”），让你触发 Bug。
5. **分析日志，验证假设**
   AI 读取你复现过程中生成的日志，判断哪些假设成立、哪些被排除。
6. **生成针对性修复方案**
   基于日志证据，AI 修改代码（如添加 localStorage、修复状态更新逻辑等）。
7. **自动清理调试代码 + 验证修复**
   修复完成后，**自动删除所有临时日志**，留下干净可提交的代码，并建议你再次测试确认。











# ASK模式

## 整体流程

**输入**

用户的自然语言问题或请求。



**上下文获取**

Cursor将以下内容作为思考的上下文。

当前光标所在的文件内容，可能会包含最近打开的文件或项目根目录下的关键文件（如 `package.json`）作为上下文。

当前通过@指定的上下文文件。

如果开启了search codebase，也会分析整个项目的内容作为上下文。



**AI 思考**

模型将问题和上下文结合起来，进行一次独立的推理和生成。

目标是生成一个准确、简洁、信息丰富的文本回复。



**输出**

一个纯文本的回复，显示在 Cursor 的聊天窗口中。

绝对不会对现有文件进行变更，也不会创建新文件。
