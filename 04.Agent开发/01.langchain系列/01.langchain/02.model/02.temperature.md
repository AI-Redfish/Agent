## temperature

`temperature` 是最常用的采样参数，用来控制模型输出的随机性。



**常见范围**

| temperature 值 | 效果 | 适用场景 |
| :-- | :-- | :-- |
| `0 ~ 0.3` | 输出稳定、保守、重复性高 | 数据提取、分类、代码生成、翻译 |
| `0.5 ~ 0.7` | 有一定灵活性，但不太跑偏 | 日常问答、总结、普通写作 |
| `0.8 ~ 1.2` | 输出更发散，表达更丰富 | 创意写作、头脑风暴 |
| `1.3 ~ 2.0` | 随机性很强，结果不稳定 | 探索性生成，不建议生产默认使用 |



**理解**

- temperature 越低，模型越倾向选择高概率 token
- temperature 越高，模型越可能尝试低概率 token
- 它本质上控制的是采样分布的平滑程度



## temperature=0

`temperature=0` 通常表示尽量走最确定的输出路径。



**效果**

- 更稳定
- 更保守
- 更接近“优先选择当前最高概率 token”



**常见场景**

- 信息抽取
- 结构化输出
- 代码生成
- 分类
- 翻译



## temperature=0 为什么输出还会不同

`temperature=0` 不等于绝对 deterministic（完全确定）。

更准确地说：

> `temperature=0` 会显著提高稳定性，但不保证每次 100% 一模一样。



**常见原因**

1. 候选 token 概率非常接近  
当两个 token 分数几乎一样时，极小差异就可能让最终结果不同。

2. 浮点计算误差  
不同硬件、不同并行顺序、不同推理内核都可能带来微小数值偏差。

3. 线上推理链路不完全固定  
多实例、负载均衡、动态 batching、不同推理节点，都可能让同样输入走到略有差异的执行路径。

4. MoE 模型的专家路由  
如果模型是 MoE 架构，专家选择边界附近也可能出现细微波动。

5. 其他参数和后处理  
`top_p`、`seed`、`stop`、安全过滤、工具返回内容等，也都可能影响最终结果。



## 和 seed 的关系

`seed` 用来提高可重复性，部分模型支持。



**理解**

- `seed` 固定随机数生成器起点
- `temperature` 控制你愿意偏离高概率答案的程度



**大致效果**

- `temperature=0`：几乎不发散，结果更稳定
- `temperature=0.7`：有一定变化
- `temperature=1.0+`：变化更大



**使用**

```python
from langchain.chat_models import init_chat_model

model = init_chat_model(
    "deepseek:deepseek-v4-flash",
    temperature=0,
    seed=42
)
```



**注意**

- 不是所有模型都支持 `seed`
- 即使支持，也不一定能保证跨硬件、跨服务节点完全一致



## 和 top_p 的关系

`top_p` 也是控制随机性的参数。



| 参数 | 控制点 |
| :-- | :-- |
| `temperature` | 调整整体概率分布的平滑程度 |
| `top_p` | 限制采样候选集合的概率范围 |



**建议**

一般只调 `temperature` 或 `top_p` 其中一个，不要同时大幅调节。



## 使用建议

**低 temperature 适合**

- 信息提取
- 结构化输出
- SQL / 代码生成
- 摘要
- 分类



**高 temperature 适合**

- 创意写作
- 文案生成
- 故事扩写
- 头脑风暴



**生产环境建议**

1. 稳定任务优先用 `0 ~ 0.3`
2. 需要更高可复现性时再考虑 `seed`
3. 不要同时激进调整 `top_p`
4. 关键任务要做输出校验，不要只依赖参数



## 案例

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

# 加载 .env
load_dotenv()

api_key = os.getenv("API_KEY")
model_name = os.getenv("MODEL")
base_url = os.getenv("BASE_URL")
model_provider = os.getenv("MODEL_PROVIDER")

headers = {
    "User-Agent": "Codex (OpenAI-Codex; +https://openai.com/codex) Python/3.12",
    "X-Client-Type": "codex"
}

question = "用一句话介绍菜鸟教程 RUNOOB"

# 低 temperature：更稳定
model_low = init_chat_model(
    model=model_name,
    model_provider=model_provider,
    api_key=api_key,
    base_url=base_url,
    default_headers=headers,
    temperature=0
)

resp1 = model_low.invoke(question)
resp2 = model_low.invoke(question)

print(f"temperature=0 第1次: {resp1.content}")
print(f"temperature=0 第2次: {resp2.content}")
print(f"两次结果相同: {resp1.content == resp2.content}")


# 高 temperature：更发散
model_high = init_chat_model(
    model=model_name,
    model_provider=model_provider,
    api_key=api_key,
    base_url=base_url,
    default_headers=headers,
    temperature=1.2
)

resp3 = model_high.invoke(question)
resp4 = model_high.invoke(question)

print(f"temperature=1.2 第1次: {resp3.content}")
print(f"temperature=1.2 第2次: {resp4.content}")
```



## 面试回答

如果被问到：

> 为什么 `temperature=0`，模型输出还会不同？



可以答：

> `temperature=0` 只是让模型尽量选择最高概率 token，提高稳定性，但不代表整个推理过程绝对确定。实际线上推理还会受浮点误差、并行计算、动态 batching、不同服务节点、MoE 路由以及其他采样或后处理参数影响。所以 temperature=0 通常更稳定，但不保证每次 100% 一致。如果要进一步提高可复现性，可以尝试固定 seed、减少其他采样参数干扰，并对关键输出做校验。`
