# 学习目标

## 本篇目标

本篇关注 LangGraph 如何表达非线性流程。掌握条件分支、循环、`Command` 和 `Send` 后，就可以构建真正的 Agent 控制流。

# 条件分支

## 基本模式

条件分支用于根据 state 决定下一步执行哪个节点。

```python
def route_by_intent(state):
    if state["intent"] == "search":
        return "search_node"
    if state["intent"] == "tool":
        return "tool_node"
    return "chat_node"

builder.add_conditional_edges("classify_intent", route_by_intent)
```

流程示意：

```text
classify_intent
  -> search_node
  -> tool_node
  -> chat_node
```

## 适用场景

条件分支适合：

- 意图识别。
- 权限判断。
- 成功/失败处理。
- 是否需要工具调用。
- 是否需要人工审批。
- 是否继续循环。

# 循环控制

## Agent 主循环

Agent 常见结构是循环：

```text
LLM 节点
  -> 判断是否调用工具
  -> 工具节点
  -> 回到 LLM 节点
  -> 没有工具调用则结束
```

示意：

```python
builder.add_node("agent", call_model)
builder.add_node("tools", call_tools)

builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", should_continue)
builder.add_edge("tools", "agent")
```

其中 `should_continue` 根据模型输出判断是否进入工具节点或结束。

## 防止无限循环

循环一定要设计退出条件：

- 最大轮次。
- 工具调用为空时退出。
- 识别到 final answer 时退出。
- 出错次数超过阈值时退出。

示例 state：

```python
class State(TypedDict):
    messages: list
    step_count: int
    max_steps: int
```

在路由函数中判断：

```python
def should_continue(state):
    if state["step_count"] >= state["max_steps"]:
        return END
    if has_tool_calls(state):
        return "tools"
    return END
```

# Command

## 基本作用

`Command` 允许一个节点同时完成两件事：

1. 更新 state。
2. 指定下一步跳转到哪个节点。

适合把“节点逻辑”和“路由决策”放在同一个函数中。

示意：

```python
from langgraph.types import Command


def classify(state) -> Command:
    if "退款" in state["question"]:
        return Command(
            update={"intent": "refund"},
            goto="refund_node",
        )
    return Command(
        update={"intent": "general"},
        goto="general_node",
    )
```

## 使用建议

适合使用 `Command` 的场景：

- 节点内部已经得出下一步，不想再写独立路由函数。
- 需要同时更新状态并跳转。
- 子图需要跳转回父图。
- interrupt 恢复后需要继续控制流程。

不建议滥用：

- 简单固定流程用普通边即可。
- 简单分支用条件边更清晰。
- 如果所有节点都用 `Command`，图结构会变得不直观。

# Send

## 基本作用

`Send` 常用于动态并行分发任务，尤其适合 map-reduce 模式。

例如把多个文档分发给多个节点处理：

```text
split_documents
  -> summarize_one(doc1)
  -> summarize_one(doc2)
  -> summarize_one(doc3)
  -> merge_summaries
```

## 适用场景

`Send` 适合：

- 多文档摘要。
- 多网页分析。
- 多子任务并行执行。
- 多 Agent 并行评审。
- 批量工具调用后合并结果。

需要注意：并行节点如果更新同一个 state key，必须配置 reducer。

# 路由函数实践

## 返回值要稳定

路由函数返回的节点名必须和 `add_node()` 注册的名字一致。建议把节点名定义成常量，避免拼写错误：

```python
NODE_SEARCH = "search"
NODE_CHAT = "chat"


def route(state):
    return NODE_SEARCH if state["intent"] == "search" else NODE_CHAT
```

## 路由函数不要做副作用

路由函数最好只做判断，不要调用外部 API、写数据库或修改 state。副作用应该放在节点里。

# START 与 END

## 虚拟节点

`START` 和 `END` 是 LangGraph 的虚拟节点：

- `START` 表示图入口。
- `END` 表示图结束。

示例：

```python
builder.add_edge(START, "first_node")
builder.add_edge("last_node", END)
```

## 路由到 END

条件边中可以返回 `END` 来结束执行：

```python
def should_continue(state):
    if state["done"]:
        return END
    return "next_node"
```

这在循环 Agent 中非常常见。
