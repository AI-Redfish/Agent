# LangGraph 是什么

LangGraph 是 LangChain 生态中面向 Agent 和复杂 LLM 工作流的底层编排框架。

它不是简单的"链式调用工具"，而是用**“图”**来表达流程：节点负责执行逻辑，边负责控制流，状态负责在节点之间传递信息。



适合使用 LangGraph 的场景：

- **多步骤 Agent**：需要在不同节点之间传递状态，且状态会随执行不断演进。
- **流程中存在条件分支、循环、重试或人工审批**：这些控制流逻辑在 LangGraph 中可以通过边和节点天然表达。
- **需要持久化执行状态，支持中断后继续运行**：LangGraph 原生支持 checkpoint 机制，可以实现断点续跑。
- **需要长期维护的生产级 Agent**：可观测性、可调试性和可测试性更好，适合持续迭代。
- **需要多 Agent 协作、子图拆分、工具调用和可观测性**：LangGraph 支持子图嵌套和层次化编排。



不一定需要 LangGraph 的场景：

- **一次简单 LLM 调用**：直接 `model.invoke()` 即可。
- **单轮问答**：无状态、无分支，无需引入编排框架。
- **只有固定顺序的两三步脚本**：`RunnableSequence` 或 `chain` 即可满足。
- **没有状态管理、恢复、分支、循环需求的轻量任务**：避免过度设计，保持简单。

## 最小概念

快速上手只需要先记住 5 个概念：

| 概念 | 含义 |
|---|---|
| `StateGraph` | 用状态图描述工作流 |
| `State` | 节点之间共享的数据结构 |
| `Node` | 一个处理函数，输入 state，返回 state 更新 |
| `Edge` | 从一个节点走到另一个节点 |
| `compile()` | 把图编译成可运行对象 |

# 最小 StateGraph

## 代码示例

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END


class State(TypedDict):
    topic: str
    joke: str


def generate_joke(state: State):
    return {"joke": f"这是一个关于 {state['topic']} 的笑话。"}


builder = StateGraph(State)
builder.add_node("generate_joke", generate_joke)
builder.add_edge(START, "generate_joke")
builder.add_edge("generate_joke", END)

graph = builder.compile()
result = graph.invoke({"topic": "LangGraph"})

print(result)
```

输出大致是：

```python
{"topic": "LangGraph", "joke": "这是一个关于 LangGraph 的笑话。"}
```

## 执行过程

执行过程可以理解为：

```text
START
  -> generate_joke
  -> END
```

节点 `generate_joke` 接收当前状态：

```python
{"topic": "LangGraph"}
```

节点返回状态增量：

```python
{"joke": "这是一个关于 LangGraph 的笑话。"}
```

LangGraph 把增量合并回 state，得到最终结果。

# 聊天 Agent 示例

## MessagesState

聊天类应用通常使用消息列表作为状态。LangGraph 提供了适合消息场景的状态结构，常见写法是使用 `MessagesState` 或自定义带 reducer 的 messages 字段。

示意代码：

```python
from langgraph.graph import StateGraph, START, END, MessagesState


def chatbot(state: MessagesState):
    response = model.invoke(state["messages"])
    return {"messages": [response]}


builder = StateGraph(MessagesState)
builder.add_node("chatbot", chatbot)
builder.add_edge(START, "chatbot")
builder.add_edge("chatbot", END)

graph = builder.compile()
```

调用时传入消息：

```python
result = graph.invoke({
    "messages": [
        {"role": "user", "content": "什么是 LangGraph？"}
    ]
})
```

## 为什么返回列表

聊天节点通常返回：

```python
{"messages": [response]}
```

而不是返回完整历史消息。原因是消息字段通常配置了 reducer，会把新消息追加到旧消息后面。

这个模式很重要：

```text
节点返回“新增内容”
LangGraph 根据 reducer 合并到状态
```

# 输入输出模式

## invoke 输入

`invoke()` 的输入必须符合图的输入状态结构：

```python
result = graph.invoke({"topic": "LangGraph"})
```

如果 state 里要求 `topic`，就必须提供 `topic`。如果缺少字段，节点读取时会报错。

## invoke 输出

`invoke()` 返回的是执行结束后的最终 state：

```python
{
    "topic": "LangGraph",
    "joke": "这是一个关于 LangGraph 的笑话。"
}
```

学习时建议先打印完整结果，不要一开始就只取某个字段。

# 调试方式

## 打印节点输入输出

初学时建议在节点函数里打印状态：

```python
def chatbot(state: MessagesState):
    print("当前消息：", state["messages"])
    response = model.invoke(state["messages"])
    print("模型回复：", response)
    return {"messages": [response]}
```

这样可以观察状态如何在节点之间流动。

## 使用 stream 观察过程

除了 `invoke()` 一次性返回结果，还可以使用 `stream()` 观察每一步输出：

```python
for event in graph.stream(input_data):
    print(event)
```

`stream()` 适合调试复杂图，因为你能看到每个节点产生了什么更新。

# 常见问题

## 忘记 compile

错误写法：

```python
graph = builder
result = graph.invoke(input_data)
```

正确写法：

```python
graph = builder.compile()
result = graph.invoke(input_data)
```

## 节点直接修改 state

不推荐：

```python
def node(state):
    state["count"] += 1
    return state
```

推荐：

```python
def node(state):
    return {"count": state["count"] + 1}
```

原因：节点应该返回状态更新，让 LangGraph 统一负责合并。

## 没有理解 START 和 END

`START` 是图的虚拟起点，`END` 是图的虚拟终点。它们不是业务节点，而是控制图执行入口和结束位置。
