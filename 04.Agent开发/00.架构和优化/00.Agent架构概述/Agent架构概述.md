# Agent 架构概述

Agent（智能体）是以 LLM 为核心、能够感知环境、自主决策并调用工具完成任务的智能系统。本文从组成部分、自主Agent、多Agent协作、AI时代的Coding模式四个维度进行梳理。



# 一、Agent 组成部分

一个典型的 Agent 由以下四大核心模块构成，常被称为"大脑 + 记忆 + 工具 + 规划"架构：

## 1. 大脑（LLM / 推理核心）

- Agent 的决策中枢，负责理解用户意图、推理分析、生成决策和输出内容。
- 决定了 Agent 的能力上限：模型越强，Agent 的理解、规划和纠错能力越强。
- 常通过 System Prompt 注入角色设定、行为约束和领域知识。

## 2. 规划（Planning）

把复杂任务拆解为可执行的步骤，是 Agent 区别于普通对话的关键能力：

- **任务分解**：将大目标拆分为有序的子任务链。
- **反思**：对已有结果进行自我审查，发现并修正错误。
- **自我修正**：根据执行反馈调整后续计划，形成"执行 - 评估 - 修正"的闭环。

## 3. 记忆

- **短期记忆**：即上下文窗口，保存当前会话中的交互信息和中间结果，受 token 限制。
- **长期记忆**：通过向量数据库（RAG）或外部存储持久化历史经验和知识，实现跨会话记忆。
- **记忆管理**：包括记忆的写入、检索、衰减与更新策略，是 Agent 工程化的重点。

## 4. 工具

LLM 本身只能生成文本，通过调用工具才能与外部世界交互：

- **函数调用**：以结构化 JSON 形式发起调用，是最主流的工具接入方式。
- **常见工具**：搜索引擎、代码执行器、数据库、文件系统、第三方 API、MCP 服务等。
- **工具协议**：MCP（Model Context Protocol）等标准化协议正在统一工具的接入方式，让工具可以跨 Agent 复用。

> 四个模块形成循环：LLM 接收输入 → 规划下一步 → 调用工具执行 → 结果写入记忆 → 继续推理，直到任务完成。



# 二、自主 Agent 的定义和特点

## 定义

自主 Agent是指在**极少人工干预**的情况下，能够自主感知环境、自主规划并自主调用工具完成任务的智能体。用户只需给出目标（甚至只给出环境事件），Agent 即可端到端地完成"感知 → 规划 → 执行 → 迭代"的全流程。

典型代表：AutoGPT、Devin、Claude Code、OpenAI Deep Research 等。

## 核心特点

1. **自主规划，自主迭代，自主调用工具完成用户任务**：
   - **自主规划**：接到目标后自行拆解任务、制定执行步骤和优先级，而非等待人类逐步下达指令。
   - **自主迭代**：执行中根据工具返回和环境反馈持续自我修正，失败时自动调整方案重试，形成"执行 - 评估 - 修正"的迭代闭环，直到任务完成。
   - **自主调用工具**：自行判断需要什么能力（搜索、代码执行、API 调用等），主动选择并组合调用工具，而非由人类预先编排好固定的调用流程。

2. **自主感知周围系统，无需人为介入自动获取并完成任务**：
   - **主动感知**：Agent 不只被动等待用户提问，而是主动监听和感知周围系统的变化——如 API 调用事件、传感器消息、日志、数据库变更、消息队列事件等。
   - **事件驱动**：环境中的事件（如传感器报警、工单创建、监控异常）自动触发 Agent 开始工作，无需人工介入发起任务。
   - **自动获取并完成任务**：从感知到信号后，自行理解事件含义、判断需要做什么、获取所需上下文和数据，自动完成任务闭环。

以上两点是自主 Agent 区别于普通 LLM 应用的本质特征，在此基础上可进一步归纳出以下衍生特点：

3. **目标驱动**：以最终目标为导向，能够坚持长程任务，跨越多轮工具调用而保持目标不漂移。

4. **自我反馈与纠错**：执行后检查结果是否符合预期，失败时自动重试或换方案。

5. **长程任务能力**：可连续执行数十甚至上百步操作，而不丢失上下文和目标。

6. **人类在环（可选）**：成熟的设计中，关键决策点仍保留人工确认机制，在自主性与可控性之间取得平衡。

> 换个角度看：普通 LLM 应用是"人驱动"——人给一步指令，AI 走一步；自主 Agent 是"目标和环境驱动"——人或环境事件给出目标后，Agent 自己走完全程。

## 与普通 LLM 应用的区别

| 维度 | 普通 LLM 对话 | 自主 Agent |
| ---- | ---- | ---- |
| 任务发起 | 由人发起每一轮对话 | 人给目标，或环境事件自动触发 |
| 环境感知 | 无，只处理输入文本 | 主动感知 API、传感器、日志等系统信号 |
| 规划方式 | 人负责拆解每一步 | Agent 自主规划任务步骤 |
| 工具使用 | 少量、由人编排 | Agent 自主选择、组合调用工具 |
| 纠错方式 | 依赖人发现问题 | 自我评估、自主迭代修正 |
| 典型场景 | 翻译、总结、写作 | 无人值守运维、自动化调研、端到端开发 |



# 三、多 Agent 协作模式

单个 Agent 的上下文和能力有限，复杂任务往往需要多个 Agent 分工协作。常见模式：

## 1. 主管模式

- 一个 Supervisor（主管）Agent 负责接收任务、拆解分发、汇总结果；多个 Worker Agent 各司其职。
- 主管是唯一的调度中心，结构清晰、易于控制，是最常用的模式（如 LangGraph 的 Supervisor 架构）。

## 2. 管道模式

- Agent 按流水线顺序工作，上游 Agent 的输出作为下游 Agent 的输入。
- 适合阶段明确的任务，如"需求分析 → 编码 → 测试 → 评审"的软件流水线。

## 3. 辩论/批判模式

- 多个 Agent 针对同一问题分别给出方案，互相质疑与辩驳，最后由裁判 Agent 或投票得出结论。
- 能显著提升答案质量、降低幻觉，常用于复杂决策和内容审查。

## 4. 小组讨论模式

- 多个 Agent 在共享环境中自由发言、传递信息，模拟团队头脑风暴。
- 信息流动灵活，但可控性较差，需要良好的协调机制。

## 5. 层级模式

- 多级主管嵌套：总主管把任务分给子主管，子主管再分给具体 Worker。
- 适合超大规模任务，如模拟一个完整的软件团队（架构组、开发组、测试组）。

## 关键设计考量

- **通信协议**：Agent 之间如何传递消息（A2A 协议、共享黑板、消息队列）。
- **状态与记忆共享**：全局状态放哪里，各 Agent 的上下文如何隔离与同步。
- **成本与延迟**：多 Agent 会成倍放大 token 消耗和响应时间，需权衡"单 Agent 多工具"与"多 Agent 分工"。
- **可控性**：协作越复杂越难调试，应优先选择最简单能解决问题的模式。



# 四、AI 时代下的 Coding 模式：基于 Spec 知识库面向 AI 开发

## 从"面向人"到"面向 AI"的转变

传统开发模式中，需求文档写给PM/架构师看，架构设计藏在工程师脑中，代码、文档、知识彼此割裂。AI 编码时代，编码的主要消费者变成了 AI Agent，于是出现了新的范式——**Spec-Driven Development（规格驱动开发）**：

> 先写清楚 Spec（规格说明），再让 AI 按 Spec 生成、修改代码。

## 核心思想

- **Spec 是唯一事实源**：需求、架构决策、技术选型、编码规范全部沉淀为结构化的 Markdown 规格文档，人和 AI 都基于同一份 Spec 工作。
- **Spec 知识库**：把散落的 wiki、会议纪要、ADR（架构决策记录）、接口约定统一组织为可检索的知识库，作为 AI 编码的上下文输入。
- **人负责 What 和 Why，AI 负责 How**：人类聚焦于定义目标与约束，具体实现交给 AI Agent，最后由人类 Review。

## 工作流程

1. **Specify（写规格）**：明确目标、功能需求、约束条件，生成 SPEC.md。
2. **Plan（做规划）**：AI 基于规格产出技术方案与架构设计，生成 PLAN.md。
3. **Tasks（拆任务）**：将方案拆解为有序、可验证的任务清单，生成 TASKS.md。
4. **Implement（执行）**：AI Agent 按任务清单逐项实现代码，人随时介入校正。
5. **Analyze（一致性检查）**：AI 反向审查代码与 Spec 的一致性，防止实现偏离意图。

## 优势

- **AI 输出可控可预测**：有清晰 Spec 约束，大幅减少 AI"自由发挥"导致的返工。
- **知识资产化**：Spec 知识库持续积累，新成员（人或 AI）都能快速上手项目。
- **天然适配多 Agent 协作**：不同 Agent（Planner / Coder / Tester）可以分别消费同一份 Spec 的不同部分。
- **降低大项目失控风险**：先规划后编码，把风险拦截在写代码之前。



# 工具推荐：GitHub Spec（spec-kit）

GitHub 官方开源的 Spec-Driven Development 工具包：**spec-kit**（https://github.com/github/spec-kit），是实践"面向 AI 开发"范式的推荐工具。

## 简介

spec-kit 提供 `/specify`、`/plan`、`/tasks`、`/analyze` 等斜杠命令，配合 GitHub Copilot、Claude Code、Gemini CLI、Cursor 等主流 AI 编码 Agent 使用，把"规格 → 规划 → 任务 → 实现 → 审查"的完整流程工程化。

## 主要能力

- **/specify**：通过交互式引导生成结构化的 SPEC.md（constitution 章程 + requirements 需求），支持中文等多语言模板。
- **/plan**：基于 Spec 自动生成 PLAN.md 技术方案。
- **/tasks**：把方案拆解为可执行、可勾选的 TASKS.md 任务清单。
- **/analyze**：对仓库做一致性分析，检查实现是否偏离 Spec。
- **多 Agent 支持**：一条命令即可初始化适配不同 AI 编码工具的工作流，无供应商锁定。
- **可自定义**：命令模板与章程均可按团队规范定制，方便与现有研发流程整合。

## 快速上手

```bash
# 安装
uvx --from git+https://github.com/github/spec-kit.git specify-cli init <项目名>

# 进入项目，配合 AI Agent 使用
/specify 实现一个用户登录模块     # 生成规格
/plan                           # 生成技术方案
/tasks                          # 拆解任务清单
# AI 按任务实现，最后 /analyze 校验一致性
```

## 适用场景

- 团队希望在引入 AI 编码的同时保持对架构和质量的掌控。
- 需要把领域知识、架构决策沉淀为可复用的 Spec 知识库。
- 多 Agent 协作开发，需要统一的事实源与任务编排。
