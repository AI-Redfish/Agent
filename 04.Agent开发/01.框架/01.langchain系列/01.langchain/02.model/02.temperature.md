# temperature

temperature越高，模型越敢选低概率token；温度越低，输出越保守。

temperature=0，每一步选择当前概率最高的token。

它本质上控制的是采样分布的平滑程度。



**常见范围**

| temperature 值 | 效果 | 适用场景 |
| :-- | :-- | :-- |
| `0 ~ 0.3` | 输出稳定、保守、重复性高。 | 数据提取、分类、代码生成、翻译 |
| `0.5 ~ 0.7` | 有一定灵活性，但不太跑偏 | 日常问答、总结、普通写作 |
| `0.8 ~ 1.2` | 输出更发散，表达更丰富 | 创意写作、头脑风暴 |
| `1.3 ~ 2.0` | 随机性很强，结果不稳定 | 探索性生成，不建议生产默认使用 |





# temperature=0输出还会不同

`temperature=0` 不等于绝对 deterministic（完全确定）。

更准确地说：

> `temperature=0` 会显著提高稳定性，但不保证每次 100% 一模一样。





TokenA：概率为0.50001。

TokenB：概率为0.49999

TokenA概率更大，应该选择TokenA。



但是底层计算可能出现很小的波动，导致：

TokenB：概率为0.50001。

TokenA ：概率为0.49999

此时选择TokenB。



当候选token概率非常接近，微小数值差异就可能让最终选择发生变化。

一段某个token选择不一样，后面整句生成路径就会跟着变。



## GPU并行与浮点数

浮点数有精度限制，不同计算顺序会有不同的舍入结果。

型推理又大量跑在GPU上，GPU会并行运算,线程调度和规约顺序可能不同.



即:浮点非结核性+并行顺序差异=logits出现细微差别.



## MOE,路由,batch

如果模型采用MOE或类似动态路由结构,token可能被分配到不同专家网络处理.

即同一个token走哪条路径可能会受路由机制影响.

而且,线上服务通常不是一个请求单独跑,而是很多用户请求一起打包成batch,batch不同,专家容量变了,路由排序变了,就可能让同一个请求的计算路径出现变化.



即:多用户i请求一起打包时,batch组成,专家容量,路由排序变化,都可能改变计算路径.



## 硬件和推理栈

不同GPU架构,精度策略,底层指令实现,都可能带来差异.

CUDA,kernel,推理引擎,算子融合方式不同,结果可能不同.

超大模型跨多卡推理,通信和同步顺序也会影响最终结果.





# 业务里怎么提高稳定性

固定模型版本,prompt模板,系统提示此和输出格式.



能设置seed就设置seed,并记录后端指纹和配置标示.



关键业务优先使用JSON,schema,Function Calling增结构化约束.



不要只做字面匹配,要做语义解析,字段校验和兜底逻辑.
