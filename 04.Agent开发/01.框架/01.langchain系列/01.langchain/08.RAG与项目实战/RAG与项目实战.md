# 检索基础

## Retrieval

检索页的主线是：先建立知识库，再把检索能力接入模型或 Agent。


**基础流程**

```text
文档加载 -> 文本切分 -> Embedding -> 向量存储 -> 检索 -> 生成答案
```


## 构建模块

检索页把核心模块拆成：

- 文档加载器
- 文本分割器
- 嵌入模型
- 向量存储
- 检索器


## 从检索到 RAG

检索不是终点，RAG 才是完整问答链路。


**常见架构**

| 架构 | 说明 |
| :-- | :-- |
| 两步 RAG | 先检索，再回答 |
| 代理式 RAG | Agent 决定是否检索、怎么检索 |
| 混合 RAG | 结合多路召回或多种策略 |


## 检索工具化

实战里通常把检索器封装成工具，让 Agent 自主决定何时查知识库。


**使用**

```python
from langchain_core.tools import tool

@tool
def search_docs(query: str) -> str:
    """从知识库检索相关文档。"""
    docs = retriever.invoke(query)
    return "\n\n".join(doc.page_content for doc in docs)
```


# 前端模式

## Frontend Overview

前端相关页面本质是在讲：如何把 Agent 的流式执行过程稳定映射到 UI。


## 渲染消息与输出

重点模式：

- Markdown 消息
- 结构化输出渲染
- 推理 token 展示
- 生成式 UI


## 展示 Agent 操作

重点模式：

- 工具调用卡片
- 人工干预审批卡片
- 执行状态展示


## 管理对话

重点模式：

- 分支聊天
- 消息队列
- 加入与重新加入流
- 时间旅行


# 常见前端模式

## Markdown 消息

适合普通聊天输出，重点是：

- 选择 Markdown 渲染库
- 做 HTML 清理
- 处理流式更新


## 工具调用可视化

适合把工具参数、结果、加载状态渲染成专门卡片，而不是塞进纯文本。


## 结构化输出渲染

适合表单、表格、对象结果展示。前端应支持部分数据渐进式渲染。


## 推理 Token

适合把模型思考过程单独折叠展示，避免和最终答案混在一起。


## 生成式 UI

生成式 UI 页的重点是：让模型返回组件规范，再由前端注册表渲染组件。

适合：

- 卡片式结果
- 可交互表单
- 动态面板


## 分支聊天

适合编辑历史消息、重新生成回答、保留多条对话分支。


## 消息队列

适合用户连续提交多条请求时排队处理，避免请求互相覆盖。


## 断线重连与时间旅行

- `join / rejoin`：适合长任务断线重连
- `time-travel`：适合基于检查点回看和恢复历史状态

# 项目实战

## Agent Chat UI

`ui` 页面本质是一个现成聊天界面方案，适合快速把 Agent 接上前端。


## 项目落地建议

- FAQ / 知识问答优先用两步 RAG
- 复杂任务再升级成 Agent 式 RAG
- 工具调用、人工审批、推理过程尽量可视化
- 长任务一定考虑消息队列、断线重连和检查点恢复
