# 内置中间件案例

LangChain 预置了一批开箱即用的中间件，覆盖**调用控制、容错、安全、上下文管理、任务规划**五大类。

本文每个中间件都给一段**最小可运行示例**，并标注实测行为与坑点。

> 中间件机制、钩子原理、自定义写法见同目录 `01.中间件Middleware.md`。
> 可运行合集：`PythonDemo/middleware/builtin_demo.py`（一键跑通本文大部分内置中间件）。
> 下文所有示例沿用同一个 `model`：
> ```python
> from langchain.chat_models import init_chat_model
> model = init_chat_model("deepseek:deepseek-v4-flash", temperature=0)
> ```


# 快速选择表

| 需求 | 用哪个中间件 |
| :-- | :-- |
| 限制模型/工具调用次数 | `ModelCallLimitMiddleware`、`ToolCallLimitMiddleware` |
| 模型调用失败重试 | `ModelRetryMiddleware` |
| 工具调用失败重试 | `ToolRetryMiddleware` |
| 主模型失败自动降级 | `ModelFallbackMiddleware` |
| 工具异常转成错误消息给模型 | `ToolErrorMiddleware` |
| 邮箱/卡号等敏感信息脱敏 | `PIIMiddleware` |
| 高风险工具人工审批 | `HumanInTheLoopMiddleware` |
| 上下文太长自动摘要 | `SummarizationMiddleware` |
| 清理旧工具结果省 token | `ContextEditingMiddleware` |
| 让 Agent 维护待办清单 | `TodoListMiddleware` |
| 工具太多，先用模型筛一遍 | `LLMToolSelectorMiddleware` |
| 给 Agent 加文件搜索能力 | `FilesystemFileSearchMiddleware` |


# 调用控制

## ModelCallLimitMiddleware

限制模型调用次数，超过后按 `exit_behavior` 处理。

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ModelCallLimitMiddleware
from langchain.messages import HumanMessage

agent = create_agent(
    model=model,
    tools=[echo],
    middleware=[
        ModelCallLimitMiddleware(
            thread_limit=20,        # 跨多次 invoke 累计上限
            run_limit=1,            # 单次 invoke 上限
            exit_behavior="end",    # "end"（默认）| "error"
        )
    ],
    system_prompt="必须调用 echo 工具。",
)

result = agent.invoke({"messages": [HumanMessage("回显 hi")]})
print(result["messages"][-1].content)
```

实测（`run_limit=1`）：

```text
Model call limits exceeded: run limit (1/1)
```

要点：

- `exit_behavior="end"`：达到上限后结束循环，并写入一条说明消息。
- `exit_behavior="error"`：直接抛异常。
- `thread_limit` 是**跨 invoke** 计数，要真正生效需要配置 `checkpointer` 并复用同一个 `thread_id`；否则每次 `invoke` 都是新状态，`thread_limit` 会退化成 `run_limit`。

## ToolCallLimitMiddleware

限制工具调用次数，可按具体工具或全部工具。

```python
from langchain.agents.middleware import ToolCallLimitMiddleware

agent = create_agent(
    model=model,
    tools=[echo],
    middleware=[
        ToolCallLimitMiddleware(
            tool_name=None,          # None = 限制所有工具
            thread_limit=20,
            run_limit=0,
            exit_behavior="continue",  # "continue"（默认）| "error" | "end"
        )
    ],
    system_prompt="必须调用 echo 工具。",
)
```

三种 `exit_behavior`：

| 值 | 行为 |
| :-- | :-- |
| `continue` | 拦截超限工具，其余流程继续（模型会收到说明并改用文字回答） |
| `error` | 抛异常 |
| `end` | 立即结束，并给每个被拦截的调用写一条 `ToolMessage` |

实测（`continue`）：模型收到"调用次数已达上限"后，改为直接用文字回复。


# 容错

## ModelRetryMiddleware

模型调用失败时按指数退避重试。

```python
from langchain.agents.middleware import ModelRetryMiddleware

agent = create_agent(
    model=model,
    tools=[search_tool],
    middleware=[
        ModelRetryMiddleware(
            max_retries=2,                 # 最多重试次数
            on_failure="continue",         # "continue" | "error"
            backoff_factor=2.0,
            initial_delay=1.0,
            max_delay=60.0,
            jitter=True,
        )
    ],
)
```

只对指定异常重试：

```python
from openai import APITimeoutError, RateLimitError

retry = ModelRetryMiddleware(
    max_retries=4,
    retry_on=(APITimeoutError, RateLimitError),  # 或传 callable 做过滤
    backoff_factor=1.5,
)
```

## ToolRetryMiddleware

工具调用失败时重试，用法与模型重试对称。

```python
from langchain.agents.middleware import ToolRetryMiddleware

agent = create_agent(
    model=model,
    tools=[flaky_tool],
    middleware=[
        ToolRetryMiddleware(
            max_retries=2,
            tools=None,              # None=所有工具；也可传 ["search"] 或工具对象
            on_failure="continue",   # "continue" | "error"
            backoff_factor=2.0,
        )
    ],
)
```

实测（`max_retries=2`）：一个总是抛 `ValueError` 的工具被调用了 **3 次**（首次 + 2 次重试），然后 `continue` 把失败结果交给模型。

> 想让重试耗尽后交给 `ToolErrorMiddleware` 处理，把 `ToolRetryMiddleware` 放在**内层**并设 `on_failure="error"`。

## ModelFallbackMiddleware

主模型失败时按顺序尝试备选模型。

```python
from langchain.agents.middleware import ModelFallbackMiddleware

agent = create_agent(
    model=model,  # 主模型
    middleware=[
        ModelFallbackMiddleware(
            fallback_model_1,   # 主模型报错后先试它
            fallback_model_2,   # 再失败再试它
        )
    ],
)
```

## ToolErrorMiddleware

把工具抛出的异常转成 `ToolMessage(status="error")` 交回模型，而不是中断整个 Agent。

```python
from langchain.agents.middleware import ToolErrorMiddleware


def on_error(exc: Exception, request) -> str | None:
    # 返回字符串 -> 转成错误 ToolMessage 交回模型
    # 返回 None   -> 异常继续向上抛，中断运行
    if isinstance(exc, ValueError):
        return f"`{request.tool_call['name']}` 执行失败，请修正参数后重试。"
    return None


agent = create_agent(
    model=model,
    tools=[flaky_tool],
    middleware=[ToolErrorMiddleware(on_error)],
)
```

要点：

- 处理是**选择性**的：只有你返回了内容的异常才会被转换，其余原样抛出。
- 不负责重试（重试交给 `ToolRetryMiddleware`）。
- 只捕获**工具执行**异常；参数校验/绑定错误由 `ToolNode` 在上游转成错误消息，不会进 `on_error`。
- 同步路径只调 `on_error`，异步路径用 `aon_error`（省略时回退到 `on_error`）。


# 安全与合规

## PIIMiddleware

检测并处理个人信息，支持 `email`、`credit_card`、`ip`、`mac_address`、`url`，也支持自定义正则。

```python
from langchain.agents.middleware import PIIMiddleware

agent = create_agent(
    model=model,
    middleware=[
        PIIMiddleware("email", strategy="redact"),
        PIIMiddleware("credit_card", strategy="mask"),
        PIIMiddleware("ip", strategy="hash"),
        # 自定义类型 + 正则
        PIIMiddleware("api_key", detector=r"sk-[a-zA-Z0-9]{32}", strategy="block"),
    ],
)
```

四种策略：

| 策略 | 效果 | 适用 |
| :-- | :-- | :-- |
| `block` | 检测到即抛异常 | 完全禁止 PII |
| `redact` | 替换为 `[REDACTED_EMAIL]` | 日志脱敏、通用合规 |
| `mask` | 部分打码 `****-****-****-1234` | 客服等需要可读性 |
| `hash` | 替换为确定性哈希 `<email_hash:a1b2c3d4>` | 分析、调试（保留可追踪性） |

实测：

```text
输入:      我的邮箱是 test@example.com
state 中:  我的邮箱是 [REDACTED_EMAIL]
```

参数：`apply_to_input=True`（默认）、`apply_to_output=False`、`apply_to_tool_results=False`，按需打开。

## HumanInTheLoopMiddleware

在高风险工具执行前暂停，等待人工审批。**必须配 `checkpointer`**。

```python
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langchain.messages import HumanMessage
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command

agent = create_agent(
    model=model,
    tools=[send_email],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "send_email": True,                       # 允许 approve/edit/reject/respond
                # 也可细粒度配置：
                # "delete_file": {"allowed_decisions": ["approve", "reject"]},
            }
        )
    ],
    checkpointer=InMemorySaver(),
    system_prompt="调用 send_email 给指定邮箱发邮件。",
)

config = {"configurable": {"thread_id": "hitl-1"}}

# 第一次调用：在工具执行前中断
result = agent.invoke(
    {"messages": [HumanMessage("给 a@b.com 发邮件，标题 hi，内容 hello")]},
    config=config,
)
print("__interrupt__" in result)   # True

# 人工审批后恢复执行
result = agent.invoke(
    Command(resume={"decisions": [{"type": "approve"}]}),
    config=config,
)
print(result["messages"][-1].content)
```

实测：`invoke` 返回中包含 `__interrupt__`（其 `value` 有 `action_requests`、`review_configs`），用 `Command(resume=...)` 恢复后正常发送。

四种决策：

| type | 说明 | 附加字段 |
| :-- | :-- | :-- |
| `approve` | 批准，按原样执行 | 无 |
| `edit` | 修改后执行 | `edited_action={"name":..., "args":...}` |
| `reject` | 拒绝，不执行 | `message`（可选拒绝理由） |
| `respond` | 人工代替工具直接回答 | `message` |

`interrupt_on` 的值：

- `True`：允许全部决策
- `False`：自动放行，不中断
- `InterruptOnConfig`：自定义 `allowed_decisions`、`description`（str 或 callable）、`when`（`ToolCallRequest -> bool` 谓词，按条件中断）


# 上下文管理

## SummarizationMiddleware

对话接近 token/消息上限时，自动把旧消息摘要压缩。

```python
from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model=model,
    middleware=[
        SummarizationMiddleware(
            model=model,                  # 也支持字符串，或 summalizer 自定义
            trigger=("messages", 50),     # ("messages", n) | ("tokens", n) | ("fraction", 0.8)
            keep=("messages", 20),        # 保留最近多少
            # 可传列表：trigger=[("fraction", 0.8), ("messages", 100)]
        )
    ],
)
```

实测（`trigger=("messages", 6)`、`keep=("messages", 2)`）：输入 7 条消息，输出被压缩到 4 条，旧内容变成摘要。

要点：

- `trigger` 支持 3 种形式，且可以传**列表**（任一命中即触发）。
- 会保证 AI/Tool 消息成对保留，不会拆散工具调用。
- 摘要生成失败会进程内重试最多 3 次；若摘要 prompt 超出上下文窗口，会切掉中间再试一次。

## ContextEditingMiddleware

上下文超过阈值时，清理旧的工具结果（当前支持 `ClearToolUsesEdit`）。

```python
from langchain.agents.middleware import ContextEditingMiddleware, ClearToolUsesEdit

agent = create_agent(
    model=model,
    tools=[...],
    middleware=[
        ContextEditingMiddleware(
            edits=[
                ClearToolUsesEdit(
                    trigger=100_000,          # 触发 token 数
                    clear_at_least=0,         # 至少清理多少 token
                    keep=3,                   # 保留最近几次工具结果
                    clear_tool_inputs=False,  # 是否同时清掉工具入参
                    exclude_tools=(),         # 排除某些工具
                    placeholder="[cleared]",
                )
            ],
            token_count_method="approximate",  # "approximate" | "model"
        )
    ],
)
```

与 `SummarizationMiddleware` 的区别：

- `Summarization` 用模型**重写**历史，保留语义，贵但信息密度高。
- `ContextEditing` **直接删除**旧工具结果并留占位符，便宜、快、无损可控。
- 常见做法：先 `ContextEditing`，不够再 `Summarization`。


# 任务与工具

## TodoListMiddleware

给 Agent 注入 `write_todos` 工具，用于复杂任务规划。

```python
from langchain.agents.middleware import TodoListMiddleware

agent = create_agent(
    model=model,
    middleware=[TodoListMiddleware()],
    system_prompt="复杂任务请使用 write_todos 规划。",
)

result = agent.invoke({"messages": [HumanMessage("帮我规划一个三步任务")]})
print(result["todos"])
```

实测输出：

```text
[{'content': '第一步：明确任务目标与范围', 'status': 'in_progress'},
 {'content': '第二步：执行核心工作', 'status': 'pending'},
 {'content': '第三步：检查与交付', 'status': 'pending'}]
```

要点：`write_todos` 每轮最多调用一次；`todos` 会写进 Agent 状态。

## LLMToolSelectorMiddleware

工具很多时，先用一个小模型筛出最相关的工具再交给主模型。

```python
from langchain.agents.middleware import LLMToolSelectorMiddleware

agent = create_agent(
    model=model,
    tools=[tool1, tool2, tool3, tool4, tool5],
    middleware=[
        LLMToolSelectorMiddleware(
            model=selector_model,      # 可选，用小模型省钱
            max_tools=3,               # 最多保留几个
            always_include=["search"], # 始终保留的工具
            max_retries=1,
        )
    ],
)
```

> ⚠️ **兼容性坑（实测）**：该中间件内部依赖模型的**结构化输出 / `response_format`**。
> 用 `deepseek-chat` 实测报错：
> ```text
> OpenAIInvalidRequestError: 400 - This response_format type is unavailable now
> ```
> 换用原生支持 `response_format` 的模型（如 OpenAI 系列）再使用。

## FilesystemFileSearchMiddleware

给 Agent 增加 `Glob`（按路径匹配）和 `Grep`（按内容搜索，优先 ripgrep，回退 Python）两个工具。

```python
from langchain.agents.middleware import FilesystemFileSearchMiddleware

agent = create_agent(
    model=model,
    tools=[],
    middleware=[
        FilesystemFileSearchMiddleware(
            root_path="/workspace",   # 搜索根目录
            use_ripgrep=True,         # 没有 rg 会自动回退
            max_file_size_mb=10,
        )
    ],
)
```


# 组合使用

## 推荐顺序

```python
from langchain.agents.middleware import (
    ModelCallLimitMiddleware,
    ToolCallLimitMiddleware,
    ModelFallbackMiddleware,
    ModelRetryMiddleware,
    ToolRetryMiddleware,
    ToolErrorMiddleware,
    PIIMiddleware,
    SummarizationMiddleware,
    ContextEditingMiddleware,
    HumanInTheLoopMiddleware,
)

agent = create_agent(
    model=model,
    tools=[search, send_email],
    middleware=[
        # 外层：调用控制 + 降级，能兜住内层所有调用
        ModelCallLimitMiddleware(thread_limit=50, run_limit=15, exit_behavior="end"),
        ToolCallLimitMiddleware(thread_limit=100, run_limit=30, exit_behavior="continue"),
        ModelFallbackMiddleware(fallback_model),
        ModelRetryMiddleware(max_retries=2),
        # 中层：上下文管理
        ContextEditingMiddleware(edits=[ClearToolUsesEdit(trigger=80_000, keep=3)]),
        SummarizationMiddleware(model=model, trigger=("fraction", 0.8), keep=("messages", 20)),
        # 内层：安全与人工，贴近真实调用
        PIIMiddleware("email", strategy="redact"),
        ToolRetryMiddleware(max_retries=2, on_failure="error"),
        ToolErrorMiddleware(on_error),
        HumanInTheLoopMiddleware(interrupt_on={"send_email": True}),
    ],
    checkpointer=InMemorySaver(),
)
```

## 组合原则

1. **限流/降级/重试在最外层**：这样它们能覆盖内层所有调用。
2. **上下文管理在中间**：保证模型看到的是压缩后的消息。
3. **审批/脱敏/拦截在最内层**：尽量贴近真实调用。
4. **`ToolRetry` 内层 + `ToolError` 外层**：让重试耗尽后的异常被 `ToolError` 捕获。
5. **包装式钩子有顺序语义**：外层能改写内层的 request，也能最后改写 response。


# 注意事项汇总

| 中间件 | 关键约束 |
| :-- | :-- |
| `ModelCallLimitMiddleware` | `thread_limit` 需 `checkpointer` + 固定 `thread_id` 才跨 run 生效 |
| `ToolCallLimitMiddleware` | `exit_behavior="continue"` 只是拦截，不会终止 Agent |
| `ModelRetryMiddleware` / `ToolRetryMiddleware` | 只对 `retry_on` 命中的异常重试 |
| `ModelFallbackMiddleware` | 只在主模型**报错**时降级，不处理业务失败 |
| `ToolErrorMiddleware` | 只处理执行异常；参数校验错误不到这里；不重试 |
| `PIIMiddleware` | 默认只处理输入，输出需显式开 `apply_to_output=True` |
| `HumanInTheLoopMiddleware` | 必须配 `checkpointer`；用 `Command(resume=...)` 恢复 |
| `SummarizationMiddleware` | 会产生额外模型调用，注意成本 |
| `ContextEditingMiddleware` | 直接删历史，可能丢失细节 |
| `TodoListMiddleware` | `write_todos` 每轮最多一次 |
| `LLMToolSelectorMiddleware` | 需要模型支持 `response_format`，DeepSeek 实测不支持 |
| `FilesystemFileSearchMiddleware` | `root_path` 控制搜索边界，注意越权 |

> ```


# 结论

- 内置中间件覆盖了 Agent 工程化里 80% 的通用需求，**优先复用，再写自定义**。
- 按"外层控制 → 中层上下文 → 内层安全"的顺序组合，能力边界最清晰。
- 涉及暂停/恢复（`HumanInTheLoop`）和跨 run 计数（`*_limit`）的能力，都要配 `checkpointer`。
- 兼容性优先：像 `LLMToolSelectorMiddleware` 依赖 `response_format`，换模型前先验证。
- 自定义中间件的机制见同目录 `01.中间件Middleware.md`。
