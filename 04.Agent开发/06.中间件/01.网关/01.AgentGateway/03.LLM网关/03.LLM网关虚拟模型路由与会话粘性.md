> 适用范围：Windows 本地 Standalone LLM Gateway 的 config.yaml 配置。回答「多模型暴露一个、按流量路由、会话固定、故障切换」四个问题。
> 依据：本地源码 commit `18f83707`（`v1.7.0-132-g18f83707`）逐条核实 + `schema/config.md`，不是纯 v1.7.0 标签。记录日期：2026-11-17。

# 能力对照

| 需求 | 是否支持 | 方式 |
| :-- | :-- | :-- |
| 多模型对外暴露一个模型名 | 支持 | `llm.virtualModels[]` + 底层模型 `visibility: internal` |
| 按流量配比路由 | 支持（有限制） | `routing.weighted` |
| 上游不可用自动切换 | 支持 | `routing.failover` + 驱逐（见下） |
| 同一会话固定同一模型 | weighted / failover 都不支持 | 见「会话粘性替代方案」 |

# 按权重路由（weighted）

```yaml
llm:
  virtualModels:
  - name: auto
    routing:
      weighted:
        targets:
        - model: sinomis/gpt-6.1-sol
          weight: 3
        - model: glm/glm-5.3-flash
          weight: 1
```

**行为与限制**

- 逐请求随机加权选择（`choose_weighted`）。同一个会话的每次请求独立随机，按权重比例分散，**不固定模型**。
- **无健康感知**：选中不可用模型时该请求直接失败，不会自动换到其他 target。
- 模型级 `llm.models[].health` 救不了 weighted：health 驱逐只作用于该模型内部 endpoint，被 weighted 选中后照样失败。

# 故障切换（failover）

```yaml
llm:
  virtualModels:
  - name: auto
    routing:
      failover:
        targets:
        - model: sinomis/gpt-6.1-sol
          priority: 0
        - model: glm/glm-5.3-flash
          priority: 0
        - model: backup-model
          priority: 1
```

**行为**

- priority 数值小的组优先。同组内按「健康分（EWMA）+ 延迟惩罚」综合评分选最优 provider。
- 整组降级时自动切到下一 priority 组。

**驱逐（eviction）启用条件，二者满足其一**

| 方式 | 效果 |
| :-- | :-- |
| 每个模型显式配 `health.eviction`（如 `consecutiveFailures: 3`） | 连续失败后驱逐，驱逐期内不接请求；基础驱逐时间默认 3 秒 |
| targets 含 ≥2 个 priority 组 | 多优先级组自动启用默认 eviction，无需显式配置 |

- 同一 priority 组且无任何 health 配置：只有软降权，**驱逐不启用**，失败模型仍持续分到流量。
- 默认不健康判定：5xx、gRPC 服务端错误、连接失败；`unhealthyExpression` 可自定义。

# 关键限制

1. weighted 与 failover 互斥（同一 enum），不能同时配置。
2. failover 的 targets 必须是具体模型，不能嵌套虚拟模型。
3. `sessionAffinity` 挂不到 LLM 虚拟模型路由：简单配置下 LLM 路由 policy 白名单仅 guardrails / 限流 / 超时 / gateway 策略。引擎侧 `affinity_key` 通道已在 `httpproxy` 的 AI 分支实现，只差配置面接线。

# 会话粘性替代方案

按推荐排序：

1. **路由级 AI 后端 + `policies.sessionAffinity`**（粘性 + 故障切换兼得）。不用 virtualModels，普通路由挂 `backends.ai.groups`，provider 用 `provider.openAI.model` 重写模型名，路由策略配 `sessionAffinity.source`（CEL 取会话标识）。引擎按一致性哈希（rendezvous hash）粘住同一 provider，且亲和不覆盖健康与优先级。限制：流量近似等分，不能任意配比。
2. **conditional 伪粘性**：按会话头 CEL 表达式确定性映射模型。零额外组件，映射固定，无健康切换。
3. **callout + cache（key = 会话 ID）**：官方 schema 明确支持的真正粘性，需要外部决策服务。
4. **改造源码**：把 SessionAffinity 接入 LLM 虚拟模型路由。
