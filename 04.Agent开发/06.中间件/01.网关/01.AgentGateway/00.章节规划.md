# 写作顺序

按依赖关系分批，每批完成并验证后再进入下一批。

| 批次 | 章节 | 理由 |
| :-- | :-- | :-- |
| A | 02 架构与配置模型 | 后续所有章节都引用 `routes` / `backends` / `policies` |
| B | 03 LLM、04 MCP | 两条主链路，跑通即可覆盖大部分使用场景 |
| C | 06 安全（入站 + 后端认证） | 上生产的前置条件 |
| D | 07 流量治理、08 可观测性、10 运维 | 运营阶段能力，依赖 B、C 的配置基础 |
| E | 09 成本与防护、06 剩余部分 | 治理能力，可独立成篇 |
| F | 05 A2A、11 集成、12 参考、13 版本 | 扩展与查询型内容 |

**每章交付标准**

1. 至少一条可执行配置，在本机跑通或明确标注未验证。
2. 配置项注明官方来源页。
3. 关键行为给出验证命令与预期输出。
4. 已知坑写入该章末尾，不散落到其他章。
