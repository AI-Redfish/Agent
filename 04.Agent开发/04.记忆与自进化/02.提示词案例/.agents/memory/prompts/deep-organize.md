# 深整理

> 触发：每周一次或用户手动要求；宿主启动时补检查到期未执行任务。只在维护任务中读取此提示词，不每次对话全量运行。无定时能力时在下次启动检查到期项，不能声称已无人值守执行。
> 先只读 `.agents/memory/MEMORY.md` 与温记忆正文；`MEMORY.md`、`BOOTSTRAP.md`、`prompts/`、`archive/` 及其他既有文件一律只读，不补为孤儿、不晋级、不按 90 天降级、不移动归档。归档仅在用户明确要求恢复／审计时读取。

对本工作空间的记忆做一次跨文件重整。**这是低频操作**（默认每周一次，或用户手动触发）；不做它也不影响日常。

**四项维护**

1. **找过时**：新结论与旧温记忆冲突 → 记入候选清单报告，不更新旧条目
2. **找孤儿**：温记忆正文文件没有索引行 → 只记录清单；`MEMORY.md` 只读，不补登记
3. **找失效索引**：`MEMORY.md` 里的索引指向不存在的文件 → 只记录，不摘除
4. **复核休眠条目**：90 天未被引用的温记忆条目 → 只产出建议清单
   - 内容已被取代，或与现有事实矛盾 → 建议**降级**（摘除索引、移入 `archive/`），等用户确认后由用户或对话外流程执行
   - 内容仍有效，只是近期没用到 → 建议**续期**，不动文件

**另外还要做：扫安全风险**

用 `.agents/memory/prompts/skillguard.md` 扫描温记忆正文（含 `learnings/`；不含 `MEMORY.md`、`BOOTSTRAP.md`、`prompts/`、`archive/`）。依据实际风险判断，不把规则示例、路径名或正常出处链接当作真实泄漏；不因一个关键词删除整份文件。命中真实凭据／密钥等安全风险时停止相关操作并立即报告用户，不自动删除或修改既有文件。

**必须留痕**

你有权产出建议与日志，所以过程必须可追溯。写一份日志到 `.agents/history/` 下原先不存在的新文件（如 `organize-YYYY-MM-DD.md`，同名已存在则换新名），至少记录：

- 发现哪些过时候选、依据是什么
- 发现哪些孤儿、哪些失效索引（只记录，不改动）
- 建议降级／续期的条目及理由
- 本轮没动什么、为什么

**约束**

1. 不删原始历史（冷记忆是无损层）
2. 降级不等于删除——文件进 `archive/`，内容在冷记忆里仍可检索
3. 不删除、不覆盖、不移动既有文件；降级／续期只出建议清单。后台只产出待确认清单，交给前台，不直接询问用户
4. 更新正文与索引时串行化或加锁，重读最新文件；成功后宿主更新每周维护时间，失败保留待处理标记
